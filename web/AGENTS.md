# Web (PWA) guide

- Production Svelte 5 + TypeScript + Vite 8 workspace (no SvelteKit), bun workspaces: `packages/{tokens,ui,api-types,client}`, `apps/{admin,public}` (separate builds, manifests, service workers), `e2e/` Playwright + axe, `scripts/` (measure, icons, fixture art). Stack record and baseline numbers: `docs/v5/pwa-stack.md`; v4 parity checklist: `docs/v5/pwa-parity.md` (update statuses when screens land); visual rules: `docs/v5/pwa-design-guidelines.md` — read its "Design principles (carried from v4)" before any UI change and check captures against it.
- Commands (from `web/`): `bun install --frozen-lockfile`, `bun run lint`, `bun run check`, `bun run test`, `bun run build`, `bun run e2e` (installed Chrome, channel `chrome`). CI runs the same in the `web` job. Pin dependencies exactly in `package.json`.
- Dev data comes from `tools/pwa-mock` (dev-only Axum mock, retired once the Rust binary serves the apps): `KANADE_MOCK_NOW` pins its clock (e2e uses Tue 29 Sep 2026 12:00 guild time), `KANADE_BOSS_DIR`/`KANADE_IDENTITY_DIR`/`KANADE_BOT_NAME` set art and identity, and `KANADE_KNOWLEDGE_DIR` (default: tracked root `boss/knowledge/`, schema v2) feeds the Bosses knowledge pages. Never hard-code dates in tests.
- Ports: dev servers default to 4173/4174 (admin/public; the parent's long-running dev mock uses 4273/4274 — leave it alone). e2e owns 4373/4374 (4383/4384 for `KANADE_REAL_ART=1` captures; parallel worktree lanes set `KANADE_E2E_PORT_BASE`, e.g. 4473/4573/4673, and real art adds 10), always starts its own mock (`reuseExistingServer: false`), and every test first checks `/__mock/whoami` reports a pwa-mock pinned at the suite's `KANADE_MOCK_NOW`, failing loudly otherwise. Never point a dev server at the e2e ports.
- Strict CSP (self only, no inline scripts/styles, report-only Trusted Types): lint bans inline `style`, Svelte transitions, `{@html}` and HTML sinks; Svelte uses `fragments: 'tree'` and `css: 'external'`; animate with CSS classes and honour reduced motion; set dynamic values via CSSOM or classes. Every e2e flow must end with zero CSP/TT reports.
- Public/admin split: the public build's `forbidModules()` guard (`apps/public/admin-only.ts`) and the bundle leak test must stay green; the public API uses its own minimised DTOs (no names, answers, party or version).
- Service workers precache static assets only, never `/api/` responses or credentials; apps must work with the SW blocked.
- Boss art is served same-origin from `/art/{portraits,icons,entry}/{key}` keyed by the catalog; missing art renders nothing. Real portraits/artwork are private and git-ignored (fine for local dev and reviews): tests and CI use the placeholder `e2e/fixtures/boss/**`. Captures are git-ignored and split so placeholders are never mistaken for the game's art: `bunx playwright test capture` writes `e2e/.captures/synthetic/`, `KANADE_REAL_ART=1 bunx playwright test capture` writes `e2e/.captures/real/`.
- Admin pages are code-split per route (`App.svelte` `PAGES`, `pages/Lazy.svelte`); the run sheet and command palette load on first use, and the planner's pointer engine (`planner/pointerDrag.ts`, `@dnd-kit/dom`) hydrates on idle or first pointer-over the board (a press that lands first is replayed once it binds) — keyboard moves in `keyboardMove.ts` (`M` on a focused card) never wait for it. Drops set the time too (`planner/dropTime.ts`, pure): after the run above (its start + `minutes`), at a day's top before the run below (its start − own minutes), an empty day keeps the time, own-time runs keep none, held to 00:00–23:59; the ghost shows "→ HH:MM" and the edge, a bar marks the card it lands next to, and changes are announced politely. Overlaps are allowed; only an overlap that shares a member (answer not no) is a clash, shown with an icon and words on the indicator and both cards, and it still saves. Keyboard Up/Down step by `run_lengths.default_minutes` (Config → Run lengths, `config/RunLengthsSection.svelte`; the store reads it once and the section updates it on save), Shift+Up jumps to just after the previous run (earlier runs' ends only), Shift+Down to just before the next (later runs' starts − own minutes only). A drop is started while the planner still holds the week, so a poll buffered during a drag or lift cannot advance the version first (the server answers 409 instead of the drop overwriting another admin's change). The whole card is the drag source (6 px travel, or a 250 ms long press on touch) with a small grip; clicks and taps still open the sheet. Stylesheets are split: `@kanade/ui/public.scss` for public, `@kanade/ui/admin.scss` for the admin shell, and page-only partials imported by their pages (`@kanade/ui/styles/<name>.scss`, incl. `settings.scss` for Config). Long tables page with `pages/Pager.svelte`. Phones get the seven-cell week rail (`WeekRail`, `_week-rail.scss`) sticky at the top of the board panel; laptop-height frames (≥900 px wide, ≤850 px tall) drop page-head prose like v4.
- Config (`apps/admin/src/config/`) is one settings window with deep-linkable sections (`/config?section=`); visited sections stay mounted so unsaved edits survive tab switches. Each section saves itself with a partial `PATCH /api/admin/config` (one section per request, arrays replaced whole; unknown/read-only keys refused with 422) and shows refusals inline; stranded reasoning resets arrive in `notices` and join the success toast. Capacity previews mirror the per-alias admission check in `config/capacity.ts`. Contracts the backend confirms: `docs/v5/admin-api.md` (every admin endpoint the PWA calls, each marked proposed) and `docs/v5/limits-contract.md`. While the portal is closed the public origin serves only the shell, status and identity.
- Area budget (pwa-design-guidelines "Area follows importance"): `e2e/layout.spec.ts` checks every screen at 1280×800, 1000×670, 1280×600, 390×844 and 844×390 — the primary surface keeps ≥ 55% of the viewport (and ≥ 360 px where the viewport is ≥ 655 px tall) and the document never scrolls. Degrade supporting rows (help → tiles → filters → status) before the surface; the short-frame rules live in `_page-furniture`, `_page-line`, `_now`, `_nav-rail`, `_shell`, `_week-head` and `_card-window`. Week has no window around its board: its header carries This/Next, the view switch and the move-help disclosure.
- Inbox (`inbox/`) is one window with Extractor / Self-service title-bar tabs, a listbox beside the detail, `?tab=&item=` deep links; in the phone frame an open item drops the page line, tabs and window chrome (`inbox--compact`), puts "‹ Inbox" in the top bar through the shell's `chrome.back()` (`BackStep`, `TopBar.svelte`), and shows the decision as a bottom action bar (pencil toggles the edit field, Reject…, Approve); Chat and Extractions filter server-side through their query string (`logs/filters.ts`, `logs/LogFilters.svelte`).
- Admin shell (M3E slice 1, gates G1/G2/G6/G7 approved 2026-10-01; spec `docs/v5/m3e-rail-design-spec.md`): `apps/admin/src/shell/` holds the navigation rail (`Rail.svelte`, `NavList.svelte`; `_nav-rail.scss`: 96 px, expanded 240 px from 1440 px wide unless collapsed — `localStorage` `rail` — and compacted to 44 px items at ≤ 760 px tall), the phone frame below 600 px wide or 500 px tall (`TopBar.svelte` — menu, title, Live chip, Inbox — + `NavDrawer.svelte` + `EdgeSwipe.svelte`, `_topbar.scss`; the drawer is the navigation, opened by the menu button or a left-edge swipe, a modal `<dialog>` that traps Tab and returns focus to the menu button unless a link changed the page) and `PageLine.svelte` (`_page-line.scss`), which every admin page uses in place of a page-head card, unboxed on the ground as in the mockups' `.top` (fidelity audit 2026-10-02): its children are the title group (breadcrumb/h1/short context; text in `--ground-ink`, deepened per face in `_contrast.scss`), and a `side` snippet holds the page's own controls, each its own chip/button/field (never other bare text on the ground); 36 px tall, controls 32 px: `title` for sections (the h1 is then the count — wrap its numerals in `.pageline__num` for the bold mono face — and the context follows after " · "), no title on detail pages (the h1 is the title), no ⓘ, and the 28 px Live chip ("Live HH:MM"; its `title` names the guild time zone, printed from 1440 px) + the "Ctrl K" Commands pill from the shell's `chrome.ts` context. Shared M3E primitives (admin only) live in `_m3e-primitives.scss`: windows flush to their panes with a 48 px title bar (8 px dots, 38 px tabs, outlined title-bar pills, a pill search with a CSS-drawn magnifier for any `[role="search"]` holding a search input), mono uppercase overlines (`.cap`, field labels, side-pane `dt`), pill buttons (`.btn--primary` accent fill, `.btn--key` 44 px, `.btn--risk` risk fill when it is the key action), connected `.seg` groups, tonal status chips, list options as `--row` cards, hover as the `--row-hover` state layer plus a neutral `--line` edge (accent 8% over the row by day, ink 7% at night; `tokens.spec` keeps it ΔE ≥ 3.5 from pane, row and `--select`), and selection as the `--select` fill with a light `--select-edge` (the selected row's "open" label is for screen readers only). Chat's per-model stats are `chat/ModelStats.svelte`: chips for the two busiest models (hidden rather than cut when the line is too narrow) and a "+n models · e errors" disclosure with the full table. On phones the page line has neither status nor Commands: the top bar shows the Live chip, and the palette is keyboard-only (Ctrl/Cmd-K, hinted in the drawer's foot beside the account; the drawer also shows Week's run count). Exactly one of rail or top bar is rendered, so `.fresh`, `.account__name` and the `Sections` nav are unique. The public app keeps `Masthead` and the 1180 px `.shell` cap. New tokens are checked in every face by `e2e/tokens.spec.ts`; the shell by `e2e/shell.spec.ts`.
- Keep the fixed `100dvh` shell with one scrolling panel at every width, v4 tokens in `packages/tokens` (approved WCAG AA overrides live only in `_contrast.scss`), keyboard alternatives for every pointer action, and focus return after dialogs, undo and route changes.

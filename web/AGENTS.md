# Web (PWA) guide

- Design spec (current, as built; overrides older design notes below where they disagree): `docs/notes/design/README.md` — read its MUST list and pre-handoff checklist before any UI or board work.
- Production Svelte 5 + TypeScript + Vite 8 workspace (no SvelteKit), bun workspaces: `packages/{tokens,ui,api-types,client}`, `apps/{admin,public}` (separate builds, manifests, service workers), `e2e/` Playwright + axe, `scripts/` (measure, icons, fixture art). Stack record and baseline numbers: `docs/notes/pwa-stack.md`; v4 parity checklist: `docs/notes/pwa-parity.md` (update statuses when screens land); visual rules: `docs/notes/pwa-design-guidelines.md` — read its "Design principles (carried from v4)" before any UI change and check captures against it.
- Commands (from `web/`): `bun install --frozen-lockfile`, `bun run lint`, `bun run check`, `bun run test`, `bun run build`, `bun run e2e` (installed Chrome, channel `chrome`). CI runs the same in the `web` job. Pin dependencies exactly in `package.json`.
- `@kanade/api-types`: never edit `src/generated.ts` (ts-rs output; regenerate from the repo root with `KANADE_WRITE_TS=1 cargo test --all-features --lib ts_bindings`); types without a typed Rust DTO stay in `src/manual.ts`.
- Dev data comes from `devtools/pwa-mock` (dev-only Axum mock, retired once the Rust binary serves the apps): `KANADE_MOCK_NOW` pins its clock (e2e uses Tue 29 Sep 2026 12:00 guild time), `KANADE_BOSS_DIR`/`KANADE_IDENTITY_DIR`/`KANADE_BOT_NAME` set art and identity, and `KANADE_KNOWLEDGE_DIR` (default: tracked root `boss/knowledge/`, schema v2) feeds the Bosses knowledge pages. Never hard-code dates in tests.
- Ports: dev servers default to 4173/4174 (admin/public; the parent's long-running dev mock uses 4273/4274 — leave it alone). e2e runs `KANADE_E2E_WORKERS` workers (default 4, max 5), each with its own pwa-mock (the mock's week is in memory and shared by both origins): worker i serves admin on base + 2i and public on base + 2i + 1, base 4373 by default (so e2e owns 4373–4382; `KANADE_REAL_ART=1` captures add 10, 4383–4392). Parallel worktree lanes set `KANADE_E2E_PORT_BASE` 100 apart, e.g. 4473/4573/4673. e2e always starts its own mocks (`reuseExistingServer: false`; servers start one by one, so the first `cargo run` builds the release mock), and every test first checks `/__mock/whoami` reports a pwa-mock pinned at the suite's `KANADE_MOCK_NOW`, failing loudly otherwise. Never point a dev server at the e2e ports.
- e2e speed: spec files run in parallel across workers; `a11y` and `capture` also spread their own tests (`mode: 'parallel'`), so every test must stand alone (the `csp` fixture resets the mock first). The full axe walk runs for the default colourway (marigold light and dark); every other colourway runs `color-contrast` on eight representative screens. Wait on conditions, not sleeps: `settle(page)` (support.ts) waits for running animations and transitions; keep `waitForTimeout` only where real time must pass (long press, idle hydration, poll intervals, "nothing changes" checks). The `csp` fixture reads the mock's report store at once and waits for late reports only when the page saw a violation.
- Strict CSP (self only, no inline scripts/styles, report-only Trusted Types): lint bans inline `style`, Svelte transitions, `{@html}` and HTML sinks; Svelte uses `fragments: 'tree'` and `css: 'external'`; animate with CSS classes and honour reduced motion; set dynamic values via CSSOM or classes. Every e2e flow must end with zero CSP/TT reports.
- Public/admin split: the public build's `forbidModules()` guard (`apps/public/admin-only.ts`) and the bundle leak test must stay green; the public app is the signed-in member portal and reads only public-origin routes (`docs/v5/api-schemas/README.md`: status, the member session, devices, `MemberWeek` and `MemberAllowance` in `public.json`), never admin routes or admin-only fields. Shared ui Week styles are imported with `$admin: false` (`apps/public/src/week/admin-week.scss`) so admin-only planner classes never reach the public bundle. Signed out, closed or denied it requests no schedule data, and member data is never persisted (the last-seen week stays in memory for offline). It reads `/api/public/status` first, then the session (`portal.svelte.ts`); writes carry the newest `X-Kanade-CSRF` any answer sent, a `401 unauthenticated` shows Session ended and a `401 reauth_required` is an `ApiRequestError` of kind `reauth` for the caller (the session stays). In e2e the mock signs the member in without Discord through `POST /__mock/public/sign-in` (`signInPublic` in `e2e/support.ts`) and `/__mock/public/{discord,end,rotate}` stand in for a sign-in outcome, an ended session and a client IP change (`devtools/pwa-mock/README.md`).
- Service workers precache static assets only, never `/api/` responses or credentials; apps must work with the SW blocked.
- Boss art is served same-origin from `/art/{portraits,icons,entry,animated}/{key}` keyed by the catalog; missing art renders nothing. On the public origin art is behind the member session and sent `private, no-cache`. Entry art renders through `BossArt` (`@kanade/ui`): the boss's looping MP4 (`animated` on `Boss`/`Knowledge`) where it has one, muted and `aria-hidden` with the still as poster, else the still; the still under reduced motion or a failed video, and off-screen clips paused. Discord (and the admin card preview, which mirrors it) stays still; the admin service worker leaves `/art/animated/` to the network, the public one all of `/art/`. Real portraits/artwork are private and git-ignored (fine for local dev and reviews): tests and CI use the placeholder `e2e/fixtures/boss/**`. Captures are git-ignored and split so placeholders are never mistaken for the game's art: `bunx playwright test capture` writes `e2e/.captures/synthetic/`, `KANADE_REAL_ART=1 bunx playwright test capture` writes `e2e/.captures/real/`. Placeholders are for automated assertions only: every visual judgement, fidelity comparison and capture shown to the user or a reviewer uses the real portraits, icons and entry art (`KANADE_REAL_ART=1`, which points the mock at root `boss/`, also for `bun run fidelity` and temporary capture specs); never present monograms, striped stand-ins or `e2e/fixtures/boss` art as the look of a screen. If root `boss/` art is missing for a key, say so rather than falling back silently.
- Admin pages are code-split per route (`App.svelte` `PAGES`, `pages/Lazy.svelte`); the run sheet and command palette load on first use, and the planner's pointer engine (`planner/pointerDrag.ts`, `@dnd-kit/dom`) hydrates on idle or first pointer-over the board (a press that lands first is replayed once it binds) — keyboard moves in `keyboardMove.ts` (`M` on a focused card) never wait for it. Drops set the time too (`planner/dropTime.ts`, pure): after the run above (its start + `minutes`), at a day's top before the run below (its start − own minutes), an empty day keeps the time, own-time runs keep none, held to 00:00–23:59; the ghost shows "→ HH:MM" and the edge, a bar marks the card it lands next to, and changes are announced politely. Overlaps are allowed; only an overlap that shares a member (answer not no) is a clash, shown with an icon and words on the indicator and both cards, and it still saves. Keyboard Up/Down step by `run_lengths.default_minutes` (Config → Run lengths, `config/RunLengthsSection.svelte`; the store reads it once and the section updates it on save), Shift+Up jumps to just after the previous run (earlier runs' ends only), Shift+Down to just before the next (later runs' starts − own minutes only). A drop is started while the planner still holds the week, so a poll buffered during a drag or lift cannot advance the version first (the server answers 409 instead of the drop overwriting another admin's change). The whole card is the drag source (6 px travel, or a 250 ms long press on touch) with a small grip; clicks and taps still open the sheet. Stylesheets are split: `@kanade/ui/public.scss` for public, `@kanade/ui/admin.scss` for the admin shell, and page-only partials imported by their pages (`@kanade/ui/styles/<name>.scss`, incl. `settings.scss` for Config). Long tables page with `pages/Pager.svelte`. Phones get the seven-cell week rail (`WeekRail`, `_week-rail.scss`) sticky at the top of the board panel; laptop-height frames (≥900 px wide, ≤850 px tall) drop page-head prose like v4.
- Config (`apps/admin/src/config/`) is one settings window with deep-linkable sections (`/config?section=`); visited sections stay mounted so unsaved edits survive tab switches. Each section saves itself with a partial `PATCH /api/admin/config` (one section per request, arrays replaced whole; unknown/read-only keys refused with 422) and shows refusals inline; stranded reasoning resets arrive in `notices` and join the success toast. Capacity previews mirror the per-alias admission check in `config/capacity.ts`. Profanity (`ProfanitySection.svelte`, `profanity.ts`, `WordPicker.svelte`): the two checks are switches (live, Undo); extra words, built-in words allowed again (a typed search over `builtin_words`, never the whole list) and the deflection line save with the bar. Contracts the backend confirms: `docs/notes/admin-api.md` (every admin endpoint the PWA calls, each marked proposed) and `docs/notes/limits-contract.md`. While the portal is closed the public origin serves only the shell, status and identity.
- Area budget (pwa-design-guidelines "Area follows importance"): `e2e/layout.spec.ts` checks every screen at 1280×800, 1000×670, 1280×600, 390×844 and 844×390 — the primary surface keeps ≥ 55% of the viewport (and ≥ 360 px where the viewport is ≥ 655 px tall) and the document never scrolls. Degrade supporting rows (help → tiles → filters → status) before the surface; the short-frame rules live in `_page-furniture`, `_page-line`, `_now`, `_nav-rail`, `_shell`, `_week-head` and `_card-window`. Week is one window: its title bar carries the Planner / Runs / Answers tabs, This/Next, Filters, the move-help disclosure, Undo and Refresh.
- Inbox (`inbox/`) is one window with Extractor / Self-service / Ownership / Past title-bar tabs (Ownership has its own `OwnershipList`/`OwnershipDetail` and never enters proposal logic), a listbox beside the detail, `?tab=&item=` deep links; in the phone frame an open item drops the page line, tabs and window chrome (`inbox--compact`), puts "‹ Inbox" in the top bar through the shell's `chrome.back()` (`BackStep`, `TopBar.svelte`), and shows the decision as a bottom action bar (pencil toggles the edit field, Reject…, Approve); Chat, Extractions and Rewrites are list-detail the same way (gate G5): one window, the list beside the open item (`/chat/:id`, `/extractions?call=`, `/rewrites?attempt=`; Rewrites reuses the Extractions window classes and `LogFilters` with `rewrites` scope: kind, stage, verdicts sent as `verdict`), one at a time below 900 px with a back step (every list-detail screen, Week run pane included, switches at the shared `SINGLE_PANE_QUERY`/`TWO_PANE_QUERY` in `packages/ui/src/media.ts` and `$single-pane`/`$two-pane` in `_breakpoints.scss`; `e2e/single-pane.spec.ts`) (a pick pushes a tagged history entry, so Back returns to the row); both filter server-side through their query string (`logs/filters.ts`, `logs/LogFilters.svelte`, a popover that closes on Escape or an outside press). A `profanity` turn opens its Conversation tab with the side, the matched word (shown in full: the bubbles carry it anyway) and the line sent, or "Retry answered cleanly".
- Empty and failed panes use `StateNote` / `LoadError` (`@kanade/ui`): a glyph, a heading, one line of text and actions (Try again, Copy details).
- The full run sheet (the pane's larger view and the phone sheet) is `RunSheet.svelte` + `_run-sheet.scss`: an identity card (clock in `--fs-hero`, `--fs-hero-narrow` on phones; sheet clock only; the run's entry art lives only inside it and the pane's `.week-pane__art`, as `.run__arts`: one picture or at most three angled slices, lead first, placed only where no text is (laptop sheet: the actions track; pane/phone: the top-right corner) — `e2e/run-identity-contrast.spec.ts` measures every word against the rendered pixels, never a text halo; a run with `fixed_id` links "View weekly timing" to `/fixed?open=`), Move and status, flush on the modal's surface over a strip of Party / Answers / Cards / Changes pill tabs — the modal is the one window, so no second title bar or dots inside it; phones put Swap, Preview ping and Reset under More actions.
- Admin shell (M3E slice 1, gates G1/G2/G6/G7 approved 2026-10-01; spec `docs/notes/m3e-rail-design-spec.md`): `apps/admin/src/shell/` holds the navigation rail (`Rail.svelte`, `NavList.svelte`; `_nav-rail.scss`: 96 px, expanded 240 px from 1440 px wide unless collapsed — `localStorage` `rail` — and compacted to 44 px items at ≤ 760 px tall), the phone frame below 600 px wide or 500 px tall (`TopBar.svelte` — menu, title, Live chip, Inbox — + `NavDrawer.svelte` + `EdgeSwipe.svelte`, `_topbar.scss`; the drawer is the navigation, opened by the menu button or a left-edge swipe, a modal `<dialog>` that traps Tab and returns focus to the menu button unless a link changed the page) and `PageLine.svelte` (`_page-line.scss`), which every admin page uses in place of a page-head card, unboxed on the ground as in the mockups' `.top` (fidelity audit 2026-10-02): its children are the title group (breadcrumb/h1/short context; text in `--ground-ink`, deepened per face in `_contrast.scss`), and a `side` snippet holds the page's own controls, each its own chip/button/field (never other bare text on the ground); 36 px tall, controls 32 px: `title` for sections (the h1 is then the count — wrap its numerals in `.pageline__num` for the bold mono face — and the context follows after " · "), no title on detail pages (the h1 is the title), no ⓘ, and the 28 px Live chip ("Live HH:MM"; its `title` names the guild time zone, printed from 1440 px) + the "Ctrl K" Commands pill from the shell's `chrome.ts` context. Shared M3E primitives (admin only) live in `_m3e-primitives.scss`: windows flush to their panes with a 48 px title bar (8 px dots, 38 px tabs, outlined title-bar pills, a pill search with a CSS-drawn magnifier for any `[role="search"]` holding a search input), mono uppercase overlines (`.cap`, field labels, side-pane `dt`), pill buttons (`.btn--primary` accent fill, `.btn--key` 44 px, `.btn--risk` risk fill when it is the key action), connected `.seg` groups, tonal status chips, list options as `--row` cards, hover as the `--row-hover` state layer plus a neutral `--line` edge (accent 8% over the row by day, ink 7% at night; `tokens.spec` keeps it ΔE ≥ 3.5 from pane, row and `--select`), and selection as the `--select` fill with a light `--select-edge` (the selected row's "open" label is for screen readers only). Chat's per-model stats are `chat/ModelStats.svelte`: chips for the two busiest models (hidden rather than cut when the line is too narrow) and a "+n models · e errors" disclosure with the full table. On phones the page line has neither status nor Commands: the top bar shows the Live chip, and the palette is keyboard-only (Ctrl/Cmd-K, hinted in the drawer's foot beside the account; the drawer also shows Week's run count). Exactly one of rail or top bar is rendered, so `.fresh`, `.account__name` and the `Sections` nav are unique. The public app keeps `Masthead` and the 1180 px `.shell` cap. New tokens are checked in every face by `e2e/tokens.spec.ts`; the shell by `e2e/shell.spec.ts`.
- Progress bars are always on (not an experiment): `WavyProgress` (`wavy={false}` for flat, `ticks`, `tone="warn"`) and the segmented `AnswerBar` (`_progress.scss`). At most two bars wave on a screen (Limits caps permit waves with `limits/permits.ts`); times come from the server clock (`Week.generated_at`, `apps/admin/src/shared/wall.ts`), never the browser's.
- Keep the fixed `100dvh` shell with one scrolling panel at every width, v4 tokens in `packages/tokens` (approved WCAG AA overrides live only in `_contrast.scss`), keyboard alternatives for every pointer action, and focus return after dialogs, undo and route changes.

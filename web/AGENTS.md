# Web (PWA) guide

- Production Svelte 5 + TypeScript + Vite 8 workspace (no SvelteKit), bun workspaces: `packages/{tokens,ui,api-types,client}`, `apps/{admin,public}` (separate builds, manifests, service workers), `e2e/` Playwright + axe, `scripts/` (measure, icons, fixture art). Stack record and baseline numbers: `docs/v5/pwa-stack.md`; v4 parity checklist: `docs/v5/pwa-parity.md` (update statuses when screens land); visual rules: `docs/v5/pwa-design-guidelines.md` — read its "Design principles (carried from v4)" before any UI change and check captures against it.
- Commands (from `web/`): `bun install --frozen-lockfile`, `bun run lint`, `bun run check`, `bun run test`, `bun run build`, `bun run e2e` (installed Chrome, channel `chrome`). CI runs the same in the `web` job. Pin dependencies exactly in `package.json`.
- Dev data comes from `tools/pwa-mock` (dev-only Axum mock, retired once the Rust binary serves the apps): `KANADE_MOCK_NOW` pins its clock (e2e uses Tue 29 Sep 2026 12:00 guild time), `KANADE_BOSS_DIR`/`KANADE_IDENTITY_DIR`/`KANADE_BOT_NAME` set art and identity, and `KANADE_KNOWLEDGE_DIR` (default: tracked root `boss/knowledge/`, schema v2) feeds the Bosses knowledge pages. Never hard-code dates in tests.
- Ports: dev servers default to 4173/4174 (admin/public; the parent's long-running dev mock uses 4273/4274 — leave it alone). e2e owns 4373/4374 (4383/4384 for `KANADE_REAL_ART=1` captures), always starts its own mock (`reuseExistingServer: false`), and every test first checks `/__mock/whoami` reports a pwa-mock pinned at the suite's `KANADE_MOCK_NOW`, failing loudly otherwise. Never point a dev server at the e2e ports.
- Strict CSP (self only, no inline scripts/styles, report-only Trusted Types): lint bans inline `style`, Svelte transitions, `{@html}` and HTML sinks; Svelte uses `fragments: 'tree'` and `css: 'external'`; animate with CSS classes and honour reduced motion; set dynamic values via CSSOM or classes. Every e2e flow must end with zero CSP/TT reports.
- Public/admin split: the public build's `forbidModules()` guard (`apps/public/admin-only.ts`) and the bundle leak test must stay green; the public API uses its own minimised DTOs (no names, answers, party or version).
- Service workers precache static assets only, never `/api/` responses or credentials; apps must work with the SW blocked.
- Boss art is served same-origin from `/art/{portraits,icons,entry}/{key}` keyed by the catalog; missing art renders nothing. Real portraits/artwork are private and git-ignored (fine for local dev and reviews): tests and CI use the placeholder `e2e/fixtures/boss/**`. Captures are git-ignored and split so placeholders are never mistaken for the game's art: `bunx playwright test capture` writes `e2e/.captures/synthetic/`, `KANADE_REAL_ART=1 bunx playwright test capture` writes `e2e/.captures/real/`.
- Admin pages are code-split per route (`App.svelte` `PAGES`, `pages/Lazy.svelte`); the run sheet and command palette load on first use, and the planner's pointer engine (`planner/pointerDrag.ts`, `@dnd-kit/dom`) hydrates on idle or first pointer-over the board (a press that lands first is replayed once it binds) — keyboard moves in `keyboardMove.ts` (`M` on a focused card) never wait for it. The whole card is the drag source (6 px travel, or a 250 ms long press on touch) with a small grip; clicks and taps still open the sheet. Stylesheets are split: `@kanade/ui/public.scss` for public, `@kanade/ui/admin.scss` for the admin shell, and page-only partials imported by their pages (`@kanade/ui/styles/<name>.scss`, incl. `settings.scss` for Config). Long tables page with `pages/Pager.svelte`. Phones get the seven-cell week rail (`WeekRail`, `_week-rail.scss`) sticky at the top of the board panel; laptop-height frames (≥900 px wide, ≤850 px tall) drop page-head prose like v4.
- Config (`apps/admin/src/config/`) is one settings window with deep-linkable sections (`/config?section=`); visited sections stay mounted so unsaved edits survive tab switches. Each section saves itself with a partial `PATCH /api/admin/config` (one section per request, arrays replaced whole; unknown/read-only keys refused with 422) and shows refusals inline; stranded reasoning resets arrive in `notices` and join the success toast. Capacity previews mirror the per-alias admission check in `config/capacity.ts`. Contracts the backend confirms: `docs/v5/admin-api.md` (every admin endpoint the PWA calls, each marked proposed) and `docs/v5/limits-contract.md`. While the portal is closed the public origin serves only the shell, status and identity.
- Area budget (pwa-design-guidelines "Area follows importance"): `e2e/layout.spec.ts` checks every screen at 1280×800, 1000×670, 1280×600, 390×844 and 844×390 — the primary surface keeps ≥ 55% of the viewport (and ≥ 360 px where the viewport is ≥ 655 px tall) and the document never scrolls. Degrade supporting rows (help → tiles → filters → status) before the surface; the short-frame rules live in `_page-furniture`, `_now`, `_nav`, `_shell`, `_week-head` and `_card-window`. Week has no window around its board: its header carries This/Next, the view switch and the move-help disclosure.
- Inbox (`inbox/`) is one window with Extractor / Self-service title-bar tabs, a listbox beside the detail, `?tab=&item=` deep links; Chat and Extractions filter server-side through their query string (`logs/filters.ts`, `logs/LogFilters.svelte`).
- Keep the fixed `100dvh` shell with one scrolling panel at every width, v4 tokens in `packages/tokens` (approved WCAG AA overrides live only in `_contrast.scss`), keyboard alternatives for every pointer action, and focus return after dialogs, undo and route changes.

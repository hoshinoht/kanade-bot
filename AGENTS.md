# Kanade bot repository guide

Kanade is a MapleStory boss-party Discord bot: a Rust v5 crate at the root plus two Svelte PWAs in `web/`. This file holds the rules that cut across subsystems. Read the nearest nested `AGENTS.md` before changing a subsystem: `crates/kanade-domain/`, `crates/kanade-llm/`, `crates/kanade-store/`, `src/api/`, `src/app/`, `src/bot/`, `src/cards/`, `src/chat/`, `src/discord/`, `src/extract/`, `tests/`, `web/`; they hold only subsystem guidance.

## Repository layout

- Root = Cargo workspace (`Cargo.toml`, edition 2024, toolchain pinned in `rust-toolchain.toml`; one `Cargo.lock`, `[profile.*]` and shared `[workspace.dependencies]` here) whose root package is the Rust v5 crate `kanade`; `crates/*` are members: `crates/kanade-log` holds the JSON log line machinery (`log!`, `event`, `emit`, and `capture`/`captured` behind `test-support`), `crates/kanade-domain` (`kanade_domain`) the pure rules (its test-only constructors behind `test-support`, which the root's `test-support` enables), `crates/kanade-store` (`kanade_store`) the SQLite store and delivery journal (its migrations, conformance suites and test stores behind `test-support`, which the root's enables), `crates/kanade-llm` (`kanade_llm`) the OpenAI-compatible model gateway provider (Kanata or another server) and governor (its fakes behind `test-support`, enabled the same way), `crates/kanade-files` (`kanade_files`) the startup file loaders (boss catalog, knowledge documents, boss art, guide sources, capped no-symlink reads). The v4 (Python) bot is retired: it is only in git history up to `fc07c48` (`git show fc07c48:legacy/python/<path>`); never re-add it. "v4" in code and docs names the behaviour v5 was ported from.
- `src/main.rs` installs the rustls `ring` provider and delegates to `src/runtime/` (command dispatch, config, JSON logs, TLS, the `serve` wiring: `serve/bot/`, `serve/web/` and their shared core); `src/cli/` parses `serve`, `healthcheck`, `models`, `backup`, `restore`, `portal`, `sessions`, `token` and the reserved `ctl`.
- Feature code: `crates/kanade-domain/` (pure rules), `crates/kanade-store/` (SQLite store + delivery journal), `src/extract/` (extraction rules and pipeline), `src/chat/` (chatbot, persona, prompts), `src/api/` (admin and public HTTP APIs, the `web` component), `src/bot/` (the Discord gateway bot, the `bot` component), the code both share: `src/app/` (scheduler writer, object-safe store reads, guild facts and staff rule, settings desk, rescans, roster persistence, the ports one side hands the other), `src/discord/` (REST transport, mentions, guild cache, identity art and portraits, member reconciliation; no gateway), `src/cards/` (card rendering, previews and wording), `crates/kanade-llm/` and `crates/kanade-files/` (see above), and `src/infrastructure/` (`scouter/` the estimate sidecar client). `api` and `bot` never import each other; `app`, `discord` and `cards` import neither, and `app` imports neither `discord` nor `cards`.
- `tests/<target>/main.rs` integration suites (see `tests/AGENTS.md`; synthetic fixtures in `tests/fixtures/`). `examples/e2e_server/` is the web apps' dev and browser e2e server (the real API over a seeded temporary store, built only with `--features test-support`), `examples/v02_quality/` the live model-quality harness, `examples/rust_e2e_fixture.rs` the `e2e:rust` fixture.
- `web/` is the production Svelte 5 PWA workspace (`web/AGENTS.md`). `scripts/` holds `boss_knowledge/` import tooling, `api_routes/route_diff.py`, the emoji pill generator and `bench_headers.py`.
- `boss/knowledge/` is the tracked boss knowledge (schema v2); `boss/portraits` and `boss/artwork` are private, git-ignored art.
- `config/personas/` tracks only `README.md`, `catalog.example.yaml`, `bundles/kanade.yaml`, `profiles/example.yaml`; everything else there is private.
- `docs/v5/` holds only the public setup guides and API schemas. Contracts, the design spec, decisions and dev logs live in the git-ignored `docs/notes/` (see its `AGENTS.md`); private captures and mockups in the git-ignored `docs/research/`. Anything others should not see goes there, never in tracked docs.
- Planning state lives in the git-ignored `.opencode/workplan/` (see "Workplans and decisions").

## Build, test and CI

- CI (`.github/workflows/ci.yml`) runs `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo test --locked --workspace --all-targets --all-features`, `cargo build --locked --release`, and the web job (lint, check, vitest, build); without `--workspace`/`--all` cargo checks only the root package, never `crates/*`. A `changes` job (dorny/paths-filter) gates each suite on its paths: when a suite starts reading a new input file, add its path to that filter.
- Cargo features `bot` (`src/bot`, twilight-gateway) and `web` (`src/api`, axum), default both; `runtime.components` may name only compiled ones. CI also runs `cargo build --locked --no-default-features --features bot` (and `web`), the same `cargo clippy -p kanade … -- -D warnings`, and `cargo tree -i` checks that the bot-only graph has no axum and the web-only graph no twilight-gateway; shared serve code lives in `runtime::serve::{composition,guild,late,health}`.
- The browser e2e (Playwright main in 4 shards plus motion, ~17 min) runs on CI only from a manual "Run workflow" with `e2e` ticked; pushes and PRs skip it, so run `bun run e2e` locally before merging web work. A manual run shares the push run's concurrency group: starting one right after a push cancels that push run (the manual run covers every job).
- After every push, confirm the push's CI run (`gh run list --workflow ci.yml --limit 3`) before calling a batch done. CI runners are 4-vCPU: wall-clock deadlines in tests must hold on a loaded debug build (master was red for two deploys when estimate chart renders missed `CHART_DEADLINE`; `[profile.dev.package.*] opt-level = 3` on the resvg/tiny-skia/png stack fixed it).
- Targets `provider_contract`, `scheduler`, `notify`, `store`, `discord`, `delivery`, `governor`, `extract`, `api`, `chat` need `required-features = ["test-support"]`; run one with `cargo test --all-features --test <name>`. `persona` and `runtime_bootstrap` are auto-discovered.
- The suite is offline (fake Discord and model providers, loopback stubs, temp stores) and never reads `.env`, `data/` or private `config/`.
- macOS checkouts are case-insensitive, CI is not: file-backed tests (boss art keys such as `MaleficStar`, persona files) use mixed-case fixtures and exact-case paths.
- `web/packages/api-types/src/generated.ts` is generated from the API DTOs (`#[cfg_attr(test, derive(ts_rs::TS))]`, list in `src/api/ts_bindings.rs`): after changing a DTO run `KANADE_WRITE_TS=1 cargo test --all-features --lib ts_bindings` (the plain test fails while it is stale). Hand-written types live in `manual.ts`.
- Pin new dependencies exactly (`=x.y.z`) with minimal features; keep rustls on `ring` only (no aws-lc/native-tls/openssl).
- `target/debug` grows past 60 GB across test and clippy batches: run `cargo clean` after each committed batch and before ending a session (in a scratch worktree, before removing it), never while a cargo or e2e run is in progress.

## Configuration, privacy and security

- Config has one owner per kind of value: image paths in `deploy/Dockerfile` `ENV`, network addresses in `deploy/compose.yaml`'s `environment:`, secrets as fixed file names in the secrets directory (`KANADE_SECRETS_DIR`, `src/runtime/secrets.rs`), deployment settings in `kanade.toml` (`KANADE_CONFIG`; template `kanade.example.toml`, whose uncommented keys under the image and Compose environment must parse, and whose `KEYS` table `docs/v5/runtime-bootstrap.md` mirrors: `src/runtime/config/file/tests.rs`), live settings in the store. A removed key or variable gets a `RETIRED` row (`file/keys.rs`) naming its new home. Non-empty `KANADE_*` variables still override keys (tests, harnesses, rehearsals; serve warns `config_shadowed`). See `docs/v5/runtime-bootstrap.md`.
- The admin and public routers are separate listeners: admin routes are never mounted on the public one.
- Treat the root `.env`, `data/`, guides and live persona paths as deployment-private. Model calls go only through `crates/kanade-llm/` to the configured OpenAI-compatible gateway (Kanata or another); never add native Ollama endpoints.
- External chat, extraction and rewrite models receive raw member names, IDs, messages and URLs; a provider's ZDR (Kanata's or another's) concerns retention, not transmission. Neither masking nor an external-unmasked opt-in exists, and both retired privacy TOML/env keys refuse startup even when false or empty. Keep historical `chat_masked` rows, and use wholly invented fixtures for model-bound tests, never real transcripts.
- Personal chatbot memory was removed in v4 and stays removed: never add per-member memory.
- Never create sessions, keys or tokens that never expire, above all on public surfaces (user rule 2026-10-05). Admin sessions stay within the `[admin]` caps (idle 5–720 min, absolute 1–168 h); new credential or session features carry an expiry inside them.
- `scouter/` (git-ignored) is the private scouter sidecar checkout: read it to confirm its API and boss keys, never copy its code into tracked files. Kanade reaches it only through `src/infrastructure/scouter/` (roster IGNs as `ign`/`igns`, nothing else); its boss keys map to the catalog in one table (`keys.rs`), and a new key needs a row and the tracked-catalog test.
- Kanade must build, test and run without the `scouter/` checkout and without `KANADE_SCOUTER_URL` (user rule 2026-10-16): no tracked file, build step, test or CI job reads `scouter/`, and with no URL every estimate feature (lookups, background refresh, charts, readings) is off while the rest works unchanged.
- Never name the scouter's upstream site in tracked code, copy or docs: say "the scouter" (UI: "Estimate"). Boss knowledge source citations (`boss/knowledge/`) are the only exception.
- Boss portraits and entry artwork are git-ignored deployment assets; their tests isolate themselves from whatever images exist locally.

## Coding policy

- Keep comments and docstrings concise.
- Prefer small, cohesive modules split by responsibility, with thin orchestration and thin entrypoints. Grow features in their subsystem directory; no catch-all runtime module, flat catch-all directories, monolithic hand-written files or empty placeholder modules. Avoid fragmentation or abstractions that only reduce line counts.
- Use the shared macros instead of hand-writing their boilerplate: `kanade_domain::spelled!` (`crates/kanade-domain/src/spelled.rs`; `Name else Error::Variant` for a typed parse error) for fieldless enums with one stored/API spelling per variant, `kanade_domain::forward_boxed!`/`forward_store!` (`crates/kanade-domain/src/forward.rs`) for trait methods that only forward or box another method, `#[derive(thiserror::Error)]` for error types (`#[error("{0}")]`, not `transparent`, unless `source()` should forward), `kanade_log::log!(level, "event", field, key = value)` for log lines (`kanade_log::event` only for prebuilt field values), and `Refusal::not_found`/`conflict`/`unprocessable`/`forbidden`/`too_many` for API refusals. In tests prefer plain helper functions to new `macro_rules!`.
- Schedule retention and expiry by monotonic elapsed time (tokio `Instant`) while passing an aware wall-clock instant into persistence, so a clock step cannot skip or repeat purge work.
- Simplification passes: exact clones are under 1% of the code and tidying tests gives 2–3%; big cuts come from removing whole layers (v4 oracle −82k, importer −2.6k). Find candidates mechanically (`pub` items or TS exports whose name appears once in the tree, files nothing imports, SCSS classes absent from markup, checking for runtime-built `block--{state}` modifiers), measure `git diff --numstat` per file and revert growth. Whole-directory review agents return "lean already" after a minute of sampling, so brief them with the candidate list, and check "reuse" claims against the exact type (`crates/kanade-llm/src/identity` has its own `Member`). Prove no behaviour change: identical test names and counts, byte-identical spellings and messages, unchanged `generated.ts` and routes, and for styles a normalised built-CSS diff plus fidelity counts.

## CHANGELOG

- Every user-visible feature, change or fix gets a bullet under the in-development version at the top of `CHANGELOG.md`. Internal refactors, test-only and CI-only changes get none.
- Format per version: `## <version>`, then `_In development_` (or the release date, `_12 Oct 2026_`), one or two plain sentences on what the release is about, an optional `> [!IMPORTANT]` upgrade-notes callout (only when an operator must act or something can't be undone), then `### New features`, `### Changes`, `### Improvements`, `### Fixes`, `### Removed`. Only sections that have bullets, in that order, and no emojis.
- One line per bullet, one sentence: lead with a past-tense verb ("Added …", "Fixed …") or "X now …", and say what a member, admin or operator sees, with screens and commands named as the user sees them. No routes, DTO fields, status codes, tables, migration numbers or file paths; a config key or env var only when an operator must set it. A fix to something added in the same release folds into its feature bullet. API detail belongs in `docs/v5/api-schemas/`, deploy steps in `deploy/README.md`.

## Workplans and decisions

- The active plan is `.opencode/workplan/kanade-v5-roadmap.{json,md}` (git-ignored); its `## Decision register` records user decisions that override older plan text. Predecessor plans are archived with their decisions and receipts.
- Record every new user decision or scope change as it happens: a JSON note in the plan AND a line in the `.md` Decision register (resume packets omit old notes). Refresh the checkpoint at every batch boundary so a compacted or fresh session resumes with full context.
- Long parent sessions die at the session byte limit (~11 MB on 2026-10-01, tipped over by reading capture PNGs inline): show captures with `browser.preview` or delegate visual checks, redirect check output to temp files and grep summaries. A dead session can be mined with `opencode session export <id> > file`.

## Agents, lanes and integration

- Parallel slices run in their own worktrees (`.worktrees/<lane>` or `../kanade-v5-<lane>`), each with its own `KANADE_E2E_PORT_BASE` (100 apart) and Playwright `--output` dir. Subagents resolve relative tool paths against the MAIN checkout, so every lane brief says "absolute paths under the worktree only"; check `git status` in the main checkout when a lane returns.
- Lane briefs forbid machine-wide `pkill -f`/`killall` (one lane once killed every cargo run across all lanes): agents stop only processes they started, by PID. If a lane reports it did this, check every running check's status file before trusting exit codes.
- A stopped subagent only loses its current turn and may keep editing: confirm it is idle in the subagent list and check `git status` before reusing its checkout.
- Reviewers (`code-checker`) have no git shell and read the MAIN checkout, not a lane: export the diff and both trees under `/private/tmp/` (`git diff base branch -- src`, `git archive <branch> <files> | tar -x -C /private/tmp/<x>-after`) and name those paths. Two reviews of one diff can disagree, so a single PASS on a large diff is not proof.
- `researcher` and `plan` agents cannot write files: save their output from `agent://<id>`. Subagents cannot read a sibling's `agent://`/`history://`: hand reports over as files. Large full-stack slices run out of one turn's budget: brief an ordered "if the budget runs short, finish 1–N first" list, resume the same agent with its "left to do", and stop any e2e servers a cut-off lane left on its port base (by PID, after checking the command line).
- Export a lane with `git add -N . && git diff HEAD --binary` (plain `git diff` drops staged `git rm`/`git mv` deletions). `git add -N .` also picks up the lane's private symlinks (`docs/notes`, `docs/research`, `boss/*`, `scouter`): `git rm -q --cached -r --ignore-unmatch` them and grep the patch's file list for those paths before applying.
- Integrate with `git add -A` on the main tree, then `git apply --3way <patch>` (it refuses a whole patch when a touched file has unstaged changes), resolve the `ours`/`theirs` blocks, `git reset -q`, and re-run fmt, clippy and the full tests before each commit; `diff -rq` the lane against main before removing its worktree. This repo uses diff3 conflict style, so also strip `||||||| base` lines, and diff the result against the original working copy. Never `git apply --unidiff-zero` a filtered hunk.
- When main already holds an earlier version of a lane's patch, apply only the delta: recreate v1 in a scratch worktree (base + v1 patch, committed), copy the lane's changed files over it, `git diff` that, then 3-way-apply the delta to main. Never copy whole files from a lane: shared files (`generated.ts`, schema README, CHANGELOG) carry other lanes' lines. After any multi-lane merge, regenerate `generated.ts` with `KANADE_WRITE_TS=1`.
- Split a shared file across commits by writing each intermediate version to a temp file and staging it with `git update-index --add --cacheinfo 100644,$(git hash-object -w <tmp>),<path>`; build each slice's index this way, check it with `git diff --cached --stat`, and prove it builds alone in a scratch `git worktree`. Never use `git stash --keep-index` (popping it over a partially staged file conflicts and the next commit swallows the other slice). A commit's path list from a patch includes both sides of `rename from`/`rename to`; stage a slice's own paths, never whole directories (`git add -A docs` once swept private captures in). The shell is zsh: pipe path lists into `xargs git add --`.
- A harness restart cancels every running shell and kills running subagents. Run long checks (merged-tree full check, Playwright, fidelity) as a detached `nohup sh script > log` that writes one exit file per step, and tell lanes to do the same. `$!` is the wrapper's PID, not the script's: find it with `pgrep -fl <script>` and wait with a native job `caffeinate -w <pid>; <summarise exit files>`, never a polling loop.
- Parallel e2e lanes push the machine load to 40–70 and motion, a11y and row-expansion tests flake: rerun a failing spec alone before calling it a regression, and run the final full suite on the merged tree with no other lane active.

## Deploy and operations

- The runbook is `deploy/README.md`; run compose from `deploy/` without `-f` so the live `compose.override.yaml` merges. A deploy: tag the running image `kanade-v5:rollback-<sha>`, test-build the image, stop the bot, tar the `kanade_v5_data` volume with a throwaway `alpine` container into `~/.config/kanade/v5/backups` (0600), snapshot with `--profile backup run --rm backup backup --name kanade-<stamp>-pre-<sha>.sqlite` (the bot refuses to start if that dir is missing), `up -d`, then `docker exec kanade-v5 /usr/local/bin/kanade healthcheck`.
- The compose build context is the working tree: with uncommitted work present, build from the commit (`git -C .. archive HEAD | docker build -f deploy/Dockerfile -t kanade-v5:local -`, then `up -d --no-build`). The build context is an allow-list (`deploy/Dockerfile.dockerignore`, `*` then `!path`): every new `COPY` source needs its own `!path/` line. CI does not build the image, so test-build it (`docker build -f deploy/Dockerfile -t kanade-v5:check .`) before tagging a rollback or stopping the bot.
- The image has no shell: inspect shipped web assets with `docker export kanade-v5 | tar -x -C <tmp>` (e.g. confirm no `data-fid` under `app/web/apps/*/dist`). The container has fixed IPs (192.168.97.10 on `kanade_edge`, from the git-ignored `compose.override.yaml`), so `docker compose run … bot <cmd>` fails with "Address already in use" while it runs: use `docker exec kanade-v5 /usr/local/bin/kanade <cmd>` for read-only checks and stop the bot first for store-owning commands.
- Never edit a shipped store migration, not even a comment: the live store checks each applied migration's checksum and refuses to start (2026-10-05 crash-loop); add a new one instead.
- Rehearse every migration on real data first: copy the latest `~/.config/kanade/v5/backups/*-pre-*.sqlite` into a fresh 0700 dir under `/private/tmp` (not `/tmp`: macOS symlinks it and the store refuses symlinked paths), run the new release binary's `kanade backup` against it with `KANADE_DB_PATH`, `KANADE_OWNER_LOCK_DIR` and `KANADE_BACKUP_DIR` pointing there (opening migrates), check the schema version and `pragma integrity_check`, then delete the copy (it is live member data).
- A fresh Docker named volume's root comes up 0755 whatever the image dir's mode: never put a privacy-checked file in a volume root; point it at a subdirectory serve creates 0700 (`/data/db`, `/chardata/db`). Moving such a file needs a one-time in-volume `mv` as uid 65532 with the bot stopped (runbook).
- Query live history on a copy: `docker run --rm -v kanade_v5_data:/data:ro alpine`, copy `/data/db/kanade.sqlite*` and open the copy (`immutable=1` misses the WAL).
- The portal is reachable only through the edge on `100.106.57.110:443`. Tailscale Serve on that port intercepts other tailnet devices (phone `SSL_PROTOCOL_ERROR`, PWA "offline") while curl from this Mac still works, so when the portal is "unreachable" check `tailscale serve status` first (Serve is off since 2026-10-01).
- A new tailnet hostname needs a DNS-only A record to 100.106.57.110 and a site block in `~/projects/personal/homelab/edge/sites/<service>/site.caddy` (not a git repo); `docker compose restart caddy` in `homelab/edge` applies it and briefly drops the portal and the Kanata gateway. A first DNS-01 attempt can fail with NXDOMAIN; Caddy retries within a minute. Review agents cannot read `~/projects/personal/homelab/kanata`: use a `researcher` for Kanata contract checks.

## Live model checks

- Live checks (`examples/v02_quality`) must mirror the deployed bot: `kanade models check` shows only env seeds, so read the saved roles from the startup `model_role` log lines and the persona from `persona_selected`, pass that bundle with `--persona-bundle` (the main checkout's private `config/personas/bundles/<name>.yaml`), and pass the saved context settings (`GET /api/admin/config` → `models.context`) as `KANADE_MODEL_CONTEXT` (otherwise window 65536, chat reserve 1024). Results are tied to the bundle's sha256.
- Run probes from a fresh detached `git worktree` at the commit under test, never a lane an agent is editing (`cargo run` builds its half-done files), and check the summary's columns against the accepted lines before trusting them: harness bugs have looked like gate failures.
- Trace a failed model call end to end: kanade's request ids (`kanade-chat-<id>-N`, `kanade-extraction-…`) appear as `client_request_id` in Kanata's access log (`docker logs kanata-kanata-1`); `outcome=cancelled` at a round duration means kanade's own deadline cut it (non-chat calls 30 s via `RetryPolicy::total_deadline`, chat rounds the question's 60 s).
- gpt-oss-120b-cloud on `high` effort spends its reasoning inside `max_output_tokens` and ends `finish=length` (`LLM completion failed (Incomplete)` while Kanata logs a 200; 14/38 V02 extractions even at reserve 6000, 0/38 on medium). Keep extraction on medium and rerun the V02 extraction cases after any effort or reserve change.
- Prompt-context changes move the chat model's tool choices (injecting the channel's runs made "anything on friday?" read only the asker). Before shipping new model-facing context, run a live V02 subset (C01 C04 C06 C08 C11 C13 C14 C15) against the deployed context and compare with the previous run.
- Rewrite prompts label the seed (`SEED_LABEL`, "Line to rewrite: …"): a bare short seed reads as a chat turn. Diagnose rejections from the admin Rewrites log (`rewrites` table) and a few live probes before changing gate rules.
- The model takes the safest option offered: a placeholder the prompt only permits ("you may tease {c3}") was used 0/20 times. Make the optional thing the line's aim, order it first and bound its length ("a few words", "hint, never quote"), or the 60-char phrase cap rejects it after the fill.

- CI's clippy and tests run only with `--all-features`, so code left used only by `test-support` items warns in the default (shipped) build without failing CI (an `Arc` import after the 2026-10-18 dead-code cleanup). After deleting or gating code, also run `cargo clippy --lib -- -D warnings`. `--all-targets` without features does not compile (unit tests need `test-support`), so don't use it as a check.
- A Config save that leaves every value unchanged writes no row (`api/admin/config/mod.rs`: only `next != current` saves), so a value still coming from a seed can't be pinned by re-saving it: change it and change it back (two History rows) before removing the seed. Check which seeded values lack rows on a store copy (`select key from config`), not from the API's `*_source` fields, which only some sections report.
- Live rehearsals of `serve` over a copy of the store use FAKE secrets (model key, NEXON key), no `discord_token` and `KANADE_COMPONENTS=web` (`KANADE_DISCORD_GATEWAY` now refuses startup), so the copy can never post to the guild, read it over REST or spend model calls; the admin session cookie is `Secure`, so curl over plain http drops it from a cookie jar: pass `Cookie:` from the sign-in's `Set-Cookie` by hand. Host ports 18090+ may be taken by Kanata; check `lsof` first.
- `@kanade/ui` declares only CSS/SCSS as side effects, so a module-level statement in a ui module (once `theme.ts`'s Dynamic palette check) runs only when some chunk uses that module's exports: code-splitting a screen silently moved it into the lazy chunk (the a11y `dynamic` specs caught it). Startup work belongs in an exported function each app's `main.ts` calls (`initExperiments`, `resumeDynamic`).
- `async move |this, lease|` closures passed to `Delivery::leased` must annotate `this: &mut Self` and must not capture borrowed arguments (`&str` ids): either makes the serve's boxed `Send` future fail with "AsyncFnOnce is not general enough". Callers with borrowed inputs build a `TickLease` and call `Delivery::finish` instead.
- `git apply --3way` is all-or-nothing: one lane deleting a file another lane modified ("patch does not apply") applies nothing, even though every other file reports "Applied … with conflicts". `git rm` those files first, re-apply with `--exclude=<path>` for each, then resolve the remaining conflict blocks. A lane branched before the root `[workspace]` existed can't run cargo inside `.worktrees/` once main has it ("believes it's in a workspace"): branch lanes from a tree that already has the workspace table.

# Chat guide

- `persona/`, `prompts/`: persona bundles and code-owned policy prompts (own contracts in `docs/v5/`).
- `gate/`: the pure answer/refuse decision (v4 `chat/gate.py`): refusal order, pilot channel allow-list (`PilotSettings`, `ChannelDirectory`, threads count as their parent), resolved mentions only, the per-person and guild-pool `RateLimiter` (monotonic seconds passed in; both read before either is spent; admins exempt), `is_bot_admin`, `retry_note`. Every refusal except a spent budget is silent.
- `authority/`: `require_authority`, the single boundary for cards about existing runs and weekly timings; enforced by the dispatcher whatever was offered.
- `tools/`: `schemas/` (verbatim v4 compact JSON per tool, never reformat; `request_tools` is v5), `read/` (pure read tools and shared helpers over a caller-loaded `ToolWorld` and `ToolContext::now`), `propose/` (proposal tools; stage only through `SchedulerService::propose`, then supersede like v4 `_record`; never write schedule rows or post cards; `when.rs` is the bounded `parse_when`), `bundles/` (dynamic tool loading: fixed bundle order READ → `request_tools` → STRATEGY → RUN_WRITES → FIXED_WRITES, code-only routing, one `request_tools` per question, a requested bundle held until `ToolOffer::begin_round` so calls are judged by the round's sent tools, refused (`close_requests`) when no round would offer it before the final no-tools round; `ToolOffer::full_set` is v4's surface byte for byte), `dispatch/` (the non-failing boundary: identity decode of arguments, read-only → unknown → unoffered refusals in that order, identity encode of every result).
- `sanitize/`: forged-note defusing, member-facing scrubbing, false-claim stripping, trusted schedule defaults, tidy bounds and schedule regrounding (v4 `agent.py` helpers). v4 lookarounds are emulated explicitly; keep them that way (`regex` has none).
- Named v5 differences: `D-PROPOSE-REFUSES` (unworkable proposals refused up front, no card), dynamic tools (vectors replay in full-set mode), `D-TOOL-ROUNDS` (8 by default), K-WHEN-SUBSET (no `dateparser`: only separator clocks after a day read literally, compact digits and bare hours keep the pm reading, matching the v4 oracle cases in `when.rs`; v4's day-of-month misreading of `sat 10` is not kept), cards are posted by the caller (tools hand over `ProposalCard`s). Personal memory is removed; do not add it.
- `context/`: in-memory per-channel history, focus, anchors and replied-author cache (monotonic seconds passed in), turn assembly and both token budgets. `answer/`: the question loop over one governed question session and one identity session (encode every prompt fragment and tool result, decode the reply), cards to `ChatPorts`, the reserved clean retry, finishing via `sanitize::shape_reply`, and the chat-log row. Contract: `docs/v5/chat-orchestration.md`; keep it in sync.
- `pilot/`: traffic and safety around a question (allowance overrides/refunds/limited reply, per-channel FIFO queue, clean-retry storm guard reserved at question start and settled in `conclude`, code-only routing, `conclude` glue with pollution containment keyed on the sticky `Generation::is_blocked` (withheld ids reloaded at startup via `reload_withheld`), the Limits snapshot). Pure state with monotonic seconds passed in; replies through `ReplyPort`. Queueing and refunds are named v5 differences from v4.
- Model calls only through `ModelClient::open_question` sessions; never call a provider or the runner directly. No Discord types here: ports only.
- Loop differences from v4 are named in `tests/chat/looping.rs` (`D-SHAPING`, `D-CLEAN-RETRY` incl. the narrowed `D-STRICT-TOOL-CALLS`, `D-USAGE-PAIRS`, `D-TYPED-FAILURES`); remove an entry only with the change that makes v5 match. Chat tool calls are validated leniently by the runner, so unknown, unoffered and schema-invalid calls reach the dispatcher: keep every handler total over coerced arguments.
- Check: `cargo test --all-features --test chat` (every family in `docs/v5/vectors/chat/`).

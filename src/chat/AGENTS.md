# Chat guide

- `persona/`, `prompts/`: persona bundles and code-owned policy prompts (own contracts in `docs/v5/`).
- `gate/`: the pure answer/refuse decision (v4 `chat/gate.py`): refusal order, pilot channel allow-list (`PilotSettings`, `ChannelDirectory`, threads count as their parent), resolved mentions only, the per-person and guild-pool `RateLimiter` (monotonic seconds passed in; both read before either is spent; admins exempt), `is_bot_admin`, `retry_note`. Every refusal except a spent budget is silent.
- `authority/`: `require_authority`, the single boundary for cards about existing runs and weekly timings; enforced by the dispatcher whatever was offered.
- `tools/`: `schemas/` (compact v4 JSON key order; named v5 differences are tested and schemas are never reformatted; `request_tools` is v5), `read/` (pure read tools and shared helpers over a caller-loaded `ToolWorld` and `ToolContext::now`), `propose/` (proposal tools; stage only through `SchedulerService::propose`, then supersede like v4 `_record`; never write schedule rows or post cards; `when.rs` is the bounded `parse_when`), `bundles/` (dynamic tool loading: fixed bundle order READ → `request_tools` → STRATEGY → RUN_WRITES → FIXED_WRITES, code-only routing, one `request_tools` per question, a requested bundle held until `ToolOffer::begin_round` so calls are judged by the round's sent tools, refused (`close_requests`) when no round would offer it before the final no-tools round; `ToolOffer::full_set` is v4's surface with named schema differences), `dispatch/` (the non-failing boundary: raw arguments, read-only → unknown → unoffered refusals in that order, raw tool results).
- `sanitize/`: forged-note defusing, member-facing scrubbing, false-claim stripping, trusted schedule defaults, tidy bounds and schedule regrounding (v4 `agent.py` helpers), and `reply_parts` (an over-bound reply as follow-up messages). `D-GROUND-FILTERED` (filtered regrounding, no cutting) is described in `docs/notes/chat-orchestration.md`. v4 lookarounds are emulated explicitly; keep them that way (`regex` has none).
- Named v5 differences: `D-AUTO-FORWARD` (`get_schedule` `week:"auto"` without a day lists the upcoming runs left in this boss week; a plain singular "next run" question (`ScheduleDefaults::next_only`, whitelisted words only, so a boss, day or other qualifier keeps the list) gets only the soonest), `D-GROUND-FILTERED` (keep the model's wording, card under: each listed run a line names by id or by a time narrowed by its stated date/weekday (`sanitize/dated.rs`) gets its record once after that paragraph; a line is replaced only when it retells a record or states an unreturned id, or a time or date no listed run has; a reply naming nothing keeps its wording with the listing after it; no word lists or boss checks, so a wrong count, status, boss or name in a kept line is an accepted gap), `D-VOICED-CARD` (the model cites runs by id; `sanitize/cite.rs` reads each cited id in a kept line as the run's bold label, and records under a kept line come without the listing heading), `D-PERSONAL-CONTEXT` (personal `get_schedule` records carry a model-only `Context (hidden from members):` line that grounding strips from the listing, and any copied label or phrase-only line from replies; curly and straight apostrophes compare equal), `D-PROPOSE-REFUSES` (unworkable proposals refused up front, no card), `D-ADD-DUPLICATE` (a one-off `propose_add` is refused, no card, while an open run in its boss week, any channel, has one of its bosses and one of its party; the refusal lists those runs and steers to `propose_move`; `extra: true` skips the check), `D-SEASONAL-LIST` (seasonal guide bosses in `list_bosses` and the related tool descriptions), dynamic tools (vectors replay in full-set mode), `D-TOOL-ROUNDS` (8 by default), K-WHEN-SUBSET (no `dateparser`: only separator clocks after a day read literally, compact digits and bare hours keep the pm reading, matching the v4 oracle cases in `when.rs`; v4's day-of-month misreading of `sat 10` is not kept), cards are posted by the caller (tools hand over `ProposalCard`s). Personal memory is removed; do not add it.
- `context/`: in-memory per-channel history, focus, anchors and replied-author cache (monotonic seconds passed in), turn assembly and both token budgets. `answer/`: the question loop over one governed question session; prompt fragments, tool results and replies are passed without identity rewriting. `PassthroughSession` is only a raw prompt-rendering helper. Cards go to `ChatPorts`, with the reserved clean retry, finishing via `sanitize::shape_reply`, the profanity guardrail (`profanity.rs`: the nudge deny-list as a live `WordFilter`; a listed question is deflected by the driver with no model call, a listed reply spends the reserved clean retry once, else the deflection line; outcome `profanity`; an exchange whose line was sent is `Conversations::exclude`d from all later context, not withheld, and its question ids reload at startup via `reload_excluded`; chat matches with `WordFilter::denied_strict` over the model's own text only, known names stripped. Wiring requirement: serve builds no `Nudger` yet; when self-service is wired, build it `.with_words(...)` from the live `v5.profanity` setting like `card_kit` does for headings), and the chat-log row. New turns do not create a masked Model view; historical masked rows remain an admin/store concern. Contract: `docs/notes/chat-orchestration.md`; keep it in sync.
- `nudge/`: rewriters implement `NudgeRewriter::rewrite_detailed` (code, route, usage vs the runner's reservation, reply, reasoning); every wrapper (`&T`, `DynRewrite`/`SharedRewriter`, serve's stop-aware one) must forward it. Call sites log one row per attempt through a `RewriteSink` (`StoreRewriteSink`: bounded write, a failure is a WARN and never changes the outcome), passing the `RewritePrompt` they sent (`RewriteAttempt.prompt`, stored as `RewritePrompt::transcript`); rows carry the persona prompt, seed and model text only, never member names or ids.
- `pilot/`: traffic and safety around a question (allowance overrides/refunds/limited reply, per-channel FIFO queue, clean-retry storm guard reserved at question start and settled in `conclude`, code-only routing, `conclude` glue with pollution containment keyed on the sticky `Generation::is_blocked` (withheld ids reloaded at startup via `reload_withheld`), the Limits snapshot). Pure state with monotonic seconds passed in; replies through `ReplyPort`. Queueing and refunds are named v5 differences from v4.
- `driver/`: serve's loop around `ChatPilot` (no Discord types; ports `Answerer` and `Surface`): gate → `Traffic` (keycap position, FIFO renumbered on every dequeue/expiry/delete; refunds on shed/delete/expiry) → admission re-checked against the live channel directory (fresh category) → armed `Held` guard, then the clean-retry reservation last in the same lock (a panic refunds and settles) → `answer` beside its `delivery.rs` (silent staging placeholder, typing ticks, withdrawal on delete) → parts edited/posted → `conclude` with that reservation (under the state lock; delivery already happened) → log row with `guardrail.delivery`. Rejected chat cards use the driver-tracked read-only `follow_up.rs`: fresh channel/source/author checks, one 30 s monotonic channel cooldown, no queue/allowance/retry reservation, generic silent staging to the card and assistant-only context anchoring (never retain its synthetic prompt or personal memory). Its armed guard spans preparation through logging; a panic/hard abort writes the shared delivery record, turns an idle staged placeholder into the failure line, then releases the channel, deferring all fallible work off a panic stack. Delivery invariants (I1–I7, D2–D5 in `docs/notes/chat-orchestration.md` "Delivery"): a started effect is always awaited; delete/cut only set flags, observed between effects; no create is replayed after ambiguity; edits/deletes get one identical retry; the shared `DeliveryRecord` is what an aborted `Held` concludes from. `start` reloads withheld ids before the driver exists. Deleting a running question never cuts it (a dispatch must finish); shutdown cuts only after a grace. Tests: `src/chat/driver/tests/` (`mod.rs` rig and driver, `delivery.rs` the R05 matrix), serve-level `src/runtime/serve/chat_tests.rs`.
- Model calls only through `ModelClient::open_question` sessions; never call a provider or the runner directly. No Discord types here: ports only.
- Loop and tool-surface differences from v4 are named in tests: `tests/chat/looping.rs` (`D-SHAPING`, `D-CLEAN-RETRY` incl. the narrowed `D-STRICT-TOOL-CALLS`, `D-USAGE-PAIRS`, `D-TYPED-FAILURES`, `D-GROUND-FILTERED`, `D-GROUND-WRITE` in `tests/chat/answer.rs`, `D-CONTEXT-BUDGET-REPLY`, `D-CONTEXT-BUDGET-RESERVE` also in `tests/chat/context.rs`, `D-SEASONAL-LIST`), `D-SEASONAL-LIST` in `tests/chat/strategy_guides.rs` and `tests/chat/tool_schemas.rs`, `D-GUESSED-RUN` in `tests/chat/guessed_run.rs` (`resolve::require_heard`: a run-taking write refuses a run the asker's words, read by the loop from the conversation as `ToolWorld::heard`, don't single out — they fit several runs or name a boss or day the run lacks), `D-RUN-CONTEXT` in `tests/chat/run_context.rs` (`context/runs.rs`: only a question replying to a bot card gets a system-prompt block of that card's runs, built by serve's `run_context` into a typed `RunContext` carried on `Prepared` and `ToolContext::run_context`, never found by searching the prompt for its header; ids, bosses, day/time and status only, every field escaped and capped, never names; `assemble` and `budgeted` take the block and trim its copy first, and drop it while the request, costed as the higher of the chat estimate and the runner's bytes / 4, overruns `CALL_TOKEN_BUDGET`; `answer/finish.rs` strips copies of it; `Heard::card` is the card's whole run list, singling out its run only when it is the one card run the words fit), `D-MIXED-PEOPLE` in `tests/chat/mixed_people.rs` (`sanitize::schedule_people` + `answer/cover.rs`: a mixed "X and I" question gets code reads for anyone the model left out and is grounded on each person's own listing, asker first, each under its own heading), and `D-ADD-DUPLICATE` in `tests/chat/duplicate_add.rs` (its `extra` schema flag in `tests/chat/tool_schemas.rs`, its token cost also in `looping.rs`, `context.rs` and `bundles.rs`); remove an entry only with the change that makes v5 match. Chat tool calls are validated leniently by the runner, so unknown, unoffered and schema-invalid calls reach the dispatcher: keep every handler total over coerced arguments.
- Check: `cargo test --all-features --test chat` (every family in `docs/v5/vectors/chat/`).

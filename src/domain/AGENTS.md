# Domain guide

- Pure v4-domain port: no I/O, no clock reads, no Discord/SQL/HTTP types. Time and IDs are injected (`scheduler::Clock`, `ids::IdGenerator`). Error `Display` strings match v4 byte-for-byte.
- `time/` (`ZonedDateTime`, `AwareDateTime`, `IsoDateTime`): Python `ZoneInfo` semantics — wall clock + zone, `fold` set only by `from_instant`, equality/hash ignore fold, UTC years 1..=9999. `weeks/`: calendar (Monday) vs reset-based boss weeks, fixed-slot placement, weekday/time parsing. `ids.rs`: UUID rows, short tags, prefix resolution. `catalog/`: boss catalog validation/parsing over decoded specs (YAML loading is infrastructure). `pytext.rs`: crate-internal Python `str` helpers (also used by `src/extract`). `members.rs`: `Member`, `Directory`, `Roster`, `PingLevel`.
- `schedule/`: pure planners over `ScheduleSnapshot` → `Draft` → `ChangeSet` (deletes before puts; atomic commit). Models v4 table rules explicitly (duplicate `(run, kind)` reminder is a no-op, rebuild deletes sent rows, past slots written as sent). Mutations emit `Notice` events, not sends.
- `history/`: attribution (`Actor`, `Surface`, `Origin`), the hash-chained change record (`kanade.change.v1` canonical sorted-key JSON, `refs`, golden vector in `docs/v5/vectors/history/`; any encoder change is a new format version) and pure revert planning (week-scoped restore, forward-only). Contract: `docs/v5/history.md`.
- `scheduler/`: mutations exist only on the per-call handle `service.as_origin(origin).<op>(..)`; a request id makes them idempotent (exact repeat → `AlreadyApplied`, same id with different arguments → `IdempotencyMismatch`); rollbacks (`revert_changes`, `restore_week_to`, `revert_by_actor`) reload and re-hash records by seq and emit one notice per affected channel. `SchedulerService` is the single write path (reads the clock once per operation, re-plans up to `COMMIT_ATTEMPTS` on `StoreError::Conflict`); `ports.rs` defines `ScheduleStore`/`Scope`.
- `notify/`: pure notification planning — mention policy, dispatch classification, digest decisions, `Notice` → `NotificationIntent`, and the `DeliveryJournal` trait/types in `journal.rs`. Planners never send, write or read a clock; execution lives in `src/bot/delivery/` against the journal.
- Deliberate v5 deviations from v4 (DST day-of clamp, fixed-edit RSVP drop, home-channel fallback, monotone digest week, `reset_to_fixed`, fixed-edit keep/update choice, attendance status pin and freeze at start) must stay named in tests; anything else must match the vectors.
- Behaviour changes require the matching vectors (`docs/v5/vectors/{domain,scheduler}/`), schemas and replay tests to change together, and only as an intentional contract change.
- Checks: unit tests are in-module (`#[cfg(test)]`); integration: `cargo test --all-features --test domain|scheduler|notify` (store parity: `--test store`).

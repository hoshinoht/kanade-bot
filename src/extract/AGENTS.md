# Extraction guide

- The rule modules below are a pure v4 `bot/extract` port: no I/O, no clock reads, no Discord/SQL/HTTP types. Reuse `domain` types (`schedule::Run`/`FixedRun`, `RsvpState`, `time::ZonedDateTime`, `weeks`, `catalog::BossTable`, `ids`) and `domain::pytext` for Python `str` semantics instead of redefining them.
- `gate/` (keyword gate, `BossLexicon`, `urgent`), `window/` (burst grouping and rescan windows), `resolve/` (literal day/time → date/clock/instant; wall-clock comparisons as v4), `matching/` (run matching over `&Run`), `merge/` (burst folding over `Amendment`), `amendment.rs` (the coerced model output).
- `schema/`: schema bytes (`text.rs`, verbatim v4 key order), `parse_response` with v4's pydantic coercions and `loc`/`type` errors, and `ExtractionAttempts`, the pure retry decision (one retry after a bad answer, carrying `retry_instruction`; transport failures, timeouts and misconfiguration end the call). `prompt/`: `SYSTEM_PROMPT`, `build_messages`, token budget, `extraction_request`. `plan/`: `plan_burst`, `one_per_run`, `consolidate` and the drop rules.
- Prompt rendering uses `PassthroughSession` only to consistently format raw author labels, mentions, names and text; message ids, member ids, URLs and model replies are not pseudonymized or decoded. A missing roster does not block a request, and provider-boundary identity scanning/`identity_leak` refusals are retired. The schema keeps `CallerValidates`; extraction parses and coerces the raw provider reply.
- Requests are shaped by the LLM runner, not here (named deviation D-SHAPING in `tests/extract/shaping.rs`). The orchestrator snapshots the extraction route, opens a governed `open_extraction_on` session on that alias, sends `complete` then, on `Next::Retry`, `answer_retry`, each built from `ExtractionAttempts::messages()` (`tests/extract/session.rs` is the reference loop).
- Orchestration (stateful, still no Discord types; contract `docs/notes/extraction-orchestration.md`): `pipeline/` (`ports.rs` message events in, `Guild`, `Proposer` = the scheduler's `propose`/`supersede_proposals`, `Outbox` for cards/chat answers/link-first redirects/backlog audit; `self_service.rs` plans links and claims the weekly tip only for a link that will be posted; `debounce.rs` per-channel 90 s bursts; `extractor.rs` flush + loading; `call.rs` the governed call; `commit.rs` proposals and one log row per call; `driver.rs` the event loop; `claims.rs` in-memory (id, content-version) claims so live bursts, backlog drains and rescans never read the same version twice — losers defer, released contended rows are re-offered; `commit` marks rows with `mark_read_exact` before any effect (at-most-once; a changed row is `stale_version` and applies nothing)), `backlog.rs` (bounded, deduplicated, drop-oldest) and `rescan/` (queued jobs over `rescan_jobs`). Time: tokio `Instant` for waits, the injected `Clock` for wall time; never `Utc::now()`. Proposals only via `Proposer`; nothing here writes schedule rows. Tests: `tests/extract/{pipeline,rescan}.rs` over `tests/extract/fakes.rs`, paused tokio time.
- `redirect.rs` (v5, no vectors): `classify` (self-service move / needs approval / weekly-timing request / unclear), `effective_mode` (cards-only while the public portal is closed) and `plan` (keep the card? which pre-filled link?). Links come from a `PortalLinks` builder; `PublicPortalLinks` route shapes are provisional until the public PWA routes are fixed. Live serve uses `PortalViewLinks` for now (user decision 2026-10-09): `{origin}/?run=<id>`, `view_only`, so the card stays in every mode, the post reads `→ see the run:` without a lead-in and no weekly tip is claimed (`SelfServiceDeps.lead_ins` is `None` in serve); switch serve to `PublicPortalLinks` plus `LeadIns` when the portal's Move and Requests screens ship. `self_service` mode and the portal switch reach the pipeline live (`Extractor::with_live_self_service`). The pipeline calls `plan` per kept change and asks `chat::nudge::Nudger::tip` for the once-per-boss-week lead-in; this module never touches the store. Tests: `tests/extract/{redirect,nudge,self_service}.rs`.
- Known difference K-TRUNCATED: a reply cut off by `max_tokens` comes back from the runner as `Incomplete` with no content, so the call ends without the answer retry v4 gave truncated JSON (same quarantine outcome); its log row keeps the reply's reported usage and reasoning, and the error text its counts. A content filter is `ContentFiltered` and logs `content_blocked`.
- Known difference K-WORD-MARKS: `regex`'s `\w` admits combining marks (U+FE0F), so `❤️930` finds no time where v4 finds `930` (`tests/extract/gate.rs`).
- Named differences D-EXTRACT-STALE-HINT and D-EXTRACT-WEEK-ANCHOR (user decision 2026-10-02, "Refuse + anchor", narrowed after review): a hint resolving only to a done or cancelled run drops kinds that act on existing runs (`needs_run`) before live/week filtering or spanning; Add/Fix keep v4 behaviour, unknown hints retain scoring, and prefixes also matching live runs are not refused. Only dayless RSVP/Sub answers reach the configured boss week of their latest known cited message creation time (burst anchor if none is known); a channel with any live runs before week filtering never falls back guild-wide for these answers. Other kinds retain v4 reachability, and bare clocks keep their implicit resolved day for every kind. RSVP/Sub ties still act. Frozen vectors stay unchanged; named overrides live in `tests/extract/matching.rs`, regressions in `tests/extract/stale_answers.rs`.
- Named difference D-NO-RSVP-SCAN (user decision 2026-10-08): `plan_burst` no longer adds an `rsvp` for a short burst line a keyword scan reads as yes/no; only RSVPs the model reports are planned. v4's `explicit_rsvp` and the burst text it read are gone (the gate's `is_agree` signal stays). Named overrides live in `tests/extract/{gate,plan}.rs`, the regression in `tests/extract/pipeline.rs`.
- Patterns use the `regex` crate (leftmost-first, like Python for lookaround-free patterns); Python's `\s` also matches U+001C..U+001F, so use `text::SPACE`. The one lookbehind (`resolve/clock.rs`) is emulated by capturing the digit.
- Behaviour must match `docs/v5/vectors/extract/{gate,window,resolve,match,merge,prompt,parse,plan}.json`, v4 quirks included, except the named differences above; only README-declared non-portable text (JSON decoder detail, pydantic prose) is normalised. Check with `cargo test --all-features --test extract`.

# Extraction guide

- The rule modules below are a pure v4 `bot/extract` port: no I/O, no clock reads, no Discord/SQL/HTTP types. Reuse `domain` types (`schedule::Run`/`FixedRun`, `RsvpState`, `time::ZonedDateTime`, `weeks`, `catalog::BossTable`, `ids`) and `domain::pytext` for Python `str` semantics instead of redefining them.
- `gate/` (keyword gate, `BossLexicon`, `urgent`), `window/` (burst grouping and rescan windows), `resolve/` (literal day/time → date/clock/instant; wall-clock comparisons as v4), `matching/` (run matching over `&Run`), `merge/` (burst folding over `Amendment`), `amendment.rs` (the coerced model output).
- `schema/`: schema bytes (`text.rs`, verbatim v4 key order), `parse_response` with v4's pydantic coercions and `loc`/`type` errors, and `ExtractionAttempts`, the pure retry decision (one retry after a bad answer, carrying `retry_instruction`; transport failures, timeouts and misconfiguration end the call). `prompt/`: `SYSTEM_PROMPT`, `build_messages`, token budget, `extraction_request`. `plan/`: `plan_burst`, `one_per_run`, `consolidate` and the drop rules.
- Every identity-bearing prompt fragment (author labels, mentions, roster and participant names, message and channel text) goes through the caller's `IdentitySession`; after parsing, reply `participants` are decoded with `decode_ref` and `summary` with `decode_reply`, and an unknown ref is a malformed answer. `Passthrough` must stay byte-identical to the vectors; `TaggingCodec` capture tests prove nothing leaks (message-id snowflakes are not member identities and stay visible).
- Requests are shaped and encoded by the LLM runner, not here (named deviation D-SHAPING in `tests/extract/shaping.rs`). `extraction_request` marks its schema `CallerValidates`, so the runner returns the raw content and extraction's parse/coerce/decode is the validator. The orchestrator opens `open_extraction`, sends `complete` then, on `Next::Retry`, `answer_retry`, each built from `ExtractionAttempts::messages()` (`tests/extract/session.rs` is the reference loop).
- Orchestration (stateful, still no Discord types; contract `docs/v5/extraction-orchestration.md`): `pipeline/` (`ports.rs` message events in, `Guild`, `Proposer` = the scheduler's `propose`/`supersede_proposals`, `Outbox` for cards/chat answers/redirect seam/backlog audit; `debounce.rs` per-channel 90 s bursts; `extractor.rs` flush + loading; `call.rs` the governed call; `commit.rs` proposals and one log row per call; `driver.rs` the event loop), `backlog.rs` (bounded, deduplicated, drop-oldest) and `rescan/` (queued jobs over `rescan_jobs`). Time: tokio `Instant` for waits, the injected `Clock` for wall time; never `Utc::now()`. Proposals only via `Proposer`; nothing here writes schedule rows. Tests: `tests/extract/{pipeline,rescan}.rs` over `tests/extract/fakes.rs`, paused tokio time.
- Known difference K-TRUNCATED: a reply cut off by `max_tokens` or a content filter comes back from the runner as `Incomplete` with no content, so the call ends without the answer retry v4 gave truncated JSON (same quarantine outcome).
- Known difference K-WORD-MARKS: `regex`'s `\w` admits combining marks (U+FE0F), so `❤️930` finds no time where v4 finds `930` (`tests/extract/gate.rs`).
- Patterns use the `regex` crate (leftmost-first, like Python for lookaround-free patterns); Python's `\s` also matches U+001C..U+001F, so use `text::SPACE`. The one lookbehind (`resolve/clock.rs`) is emulated by capturing the digit.
- Behaviour must match `docs/v5/vectors/extract/{gate,window,resolve,match,merge,prompt,parse,plan}.json`, v4 quirks included; only README-declared non-portable text (JSON decoder detail, pydantic prose) is normalised. Check with `cargo test --all-features --test extract`.

# Store guide

- `sqlite/` and `order.rs` are production code; `memory/`, `conformance.rs`, `journal_conformance.rs`, `history_conformance.rs`, `draft_conformance.rs`, `precondition_conformance.rs`, `cherry_pick_conformance.rs`, `attendance_conformance.rs`, `model_log_conformance.rs`, `proposal_conformance.rs` and `settings_conformance.rs` compile only under `cfg(test)` or feature `test-support`. Every store must pass all conformance suites; add new behavioural checks there, not in one backend's tests.
- Runtime settings use allowlisted `config` rows (`sqlite/settings.rs`, `memory/settings.rs`); `v5.profile_visibility` is persisted as an ordered deduplicated list, with a missing row defaulting to empty/private and no schema migration.
- `sqlite/`: `connect.rs` (foreign keys, WAL, `busy_timeout`, `synchronous=FULL` on every connection), `migrate.rs` + `migrations/NNNN_*.sql`, `rows.rs` (UTC ISO text timestamps at µs precision, JSON lists), `schedule.rs` (`ScheduleStore`), `writer.rs`, `owner.rs` (ownership), `backup.rs`, `journal/` (`DeliveryJournal`, `CardIndex`), `history.rs`, `drafts.rs` (`DraftStore`: one read txn for `snapshot_with_head`; one `BEGIN IMMEDIATE` per create/update/`commit_merge`/`expire_drafts`; `records_after` maps an unparseable record to `HistoryGap::Tampered`).
- Ownership (`owner.rs`, per `docs/notes/maintenance-contract.md` "v5 store deltas"): `SqliteStoreConfig { db_path, owner_lock_dir }`; paths must be absolute and canonical with no symlinks (macOS: `/private/var`); the lock dir is uid-owned 0700, the DB dir private, the DB file 0600. The DB inode is opened before locking `kanade-{dev:x}-{ino:x}.lock` (no-follow, 0600, one link); a process registry keyed by (dev, inode) refuses second owners; every write transaction, reconnect and backup re-verifies the path still names the owned inode (`IdentityChanged`). `open` and `restore` run in their own tasks so ownership is released only after SQLite closes.
- No SQLite authorizer yet (sqlx exposes no hook): all SQL must stay constant with bound parameters. Adding any caller-influenced SQL requires the deny-by-default authorizer first (release gate). `Backend` error text may contain paths — never surface it to users.
- Commits: `BEGIN IMMEDIATE`, replay a recorded request id (`AlreadyApplied`/`IdempotencyMismatch`), check declared edit preconditions against `change_fields` (`StaleEdit`), then check the store `revision` (`StoreError::Conflict` if stale), collapse puts per key, delete touched keys then insert final rows (UNIQUE can't be deferred), deferred FKs for reminders/RSVPs → runs, bump `revision`. No FK from delivery targets to native rows (bound claims outlive native rows).
- The writer connection is taken out of its slot for each transaction; a cancelled or failed transaction orphans it and the next write reconnects. `close()` is required: it awaits orphans before releasing ownership.
- Migrations: add `migrations/NNNN_name.sql` and append a `Migration { version, sql: include_str!(..) }` entry to `MIGRATIONS` in `migrate.rs` with the next contiguous version (current: `0001_init` through `0025_session_avatar`). v19+: an older image refuses the store (`FutureVersion`); rollback = old image + pre-deploy tarball and rolls back the WHOLE store (schedule, history, delivery journal, drafts, settings), so prefer a forward fix.
- Members (`0010`, `sqlite/members.rs`, `domain::members::MemberStore`): `members` gains `aliases`/`roles` (JSON arrays), `reply_style` and `is_guild_admin`; `member_aliases` (PK alias) keeps aliases unique across members and is rewritten with the row on every `put_member` (an upsert, never `REPLACE`, which would cascade-delete the aliases). `members_conformance` covers both stores. Applied versions are SHA-256 checksummed; never edit an applied migration.
- Backups: `VACUUM INTO` a 0700 staging dir, file 0600, published by hard link (never overwrites). Restore validates the copy first and refuses if the DB or its `-wal`/`-shm`/`-journal` exists.
- History: every non-empty commit appends a change record in the same transaction (`change_log`, `change_log_weeks`; triggers refuse UPDATE/DELETE); request ids are unique per actor with a stored request digest; verification hashes the stored bytes; backups write `<backup>.manifest.json` with the history head used as an anchor (`open_with_anchor`). Journal writes advance the revision without a record.
- Drafts (`0005`): `drafts`, `draft_ops`, append-only `draft_events`, `draft_requests` (create idempotency per author). CHECKs: `status='merged'` ⇔ `merged_seq` set; a closed status (merged/discarded/rejected/withdrawn/expired) ⇔ `closed_by_*` set (expiry uses the system `delivery` actor). `commit_merge` is one txn: request-id replay → draft live at version (else `Stale`) → revision (`Conflict`) → rows + record + blame + draft merged + event; empty change sets are refused; only `commit_merge` sets merged. The memory store mirrors all of this.
- Attendance (`0006`): standing answers and `attendance_default` live on the fixed-run row (`standing_answers` table written with it), recorded attendance on the run row (`run_attendance`); all three are history-recorded, blamed (`standing:<user>`, `attendance_default`, `attended:<user>`) and returned by `read_versioned`. A hand-set v5 status pin (`Run.status_pin`) is stored in `run_status_pins` with the run row and blamed as the run's `status_pin` field; the change record carries it only when set. `member_history` is one constant `ROW_NUMBER()` query per timing. The service's attendance policy is the single source: calls carrying a mismatching `SchedulePolicy.attendance` are refused (`AttendanceMismatch`).
- Model logs (`0007`, `sqlite/model_log/`, `ModelLogStore`): `messages` (watched cache; an edit with new content clears `processed_at`), insert-only `extractions` + `chat_interactions`/`chat_rounds` (typed outcome CHECKs from `docs/notes/admin-api.md` plus `unknown`; guardrail JSON object; `clean_retry`/`withheld` flags also match those outcome filters), derived filter tables `extraction_members`/`chat_tools`, `rescan_jobs` (final status never changes), `chat_allowance_overrides`, `self_service_tips` (PK member+week; `INSERT OR IGNORE` claim). Filters are one constant query each (`?n IS NULL OR …`, `json_each` for outcome sets), newest first with an `(at, id)` keyset cursor; `q` is ASCII case-insensitive (`instr(lower())`), mirrored by the memory store. Because `?n IS NULL OR col = ?n` defeats per-column indexes, lists are bounded scans of the `(at, id)` index (retention bounds the table); the channel-message read uses two constant variants so pending reads hit `messages_unprocessed`. The extraction list has a second constant variant without `prompt`/`raw_response` (`ExtractionFilter::omit_bodies`); a chat page loads its rounds in one `json_each` query; `messages_by_ids` reads by primary key. `mark_read_exact` (extraction's at-most-once mark before effects) checks every row's content then writes in one `BEGIN IMMEDIATE`, all or nothing; a repeated id counts once. `sqlite/model_log/plans.rs` pins the plans with `EXPLAIN QUERY PLAN` and fails on any unused log index (`0008` dropped `chat_member`, `chat_latency`, `extraction_members_member`). Retention (`0008`, user decision: 90 days, `DEFAULT_LOG_RETENTION`): `prune_model_logs(before)` deletes logs with `at < before` (children first) and processed messages created before it, `PRUNE_BATCH` rows per table per `BEGIN IMMEDIATE`, looping until a batch comes back short; logs refuse UPDATE by trigger but allow this DELETE. `store_error` maps trigger `RAISE`s (`SQLITE_CONSTRAINT_TRIGGER`, code 1811, `Other` in sqlx 0.8.6) to `Constraint`.
- Proposals (`0007`, `sqlite/proposals.rs`, `ProposalStore`): an `admin` `drafts` row plus a `draft_proposals` row (triggers: system author + `admin` kind only, never updated/deleted) reads as `DraftKind::Proposal`; create supersedes same-key live proposals (discarded, reason `superseded`) in one txn; TTL expiry by `expires_at`; merges only via `commit_merge`. Proposal cards (`0011`, `sqlite/proposal_cards.rs`, `ProposalCardStore`, `card_conformance`): details written once per proposal (same details again a no-op), bound only by the journal's `card` target (`message_id`/`posted_at`; a trigger refuses other updates and deletes); `0011` also adds `extractions.refusals` (JSON array of `{change, code, message}`). `sqlite/txn.rs` holds the shared `write_txn!`/`read_txn!` macros.
- Notice outbox (`0012`, `sqlite/journal/outbox.rs` + versioned `payload.rs`, `memory/outbox.rs`, `outbox_conformance`): `ChangeMeta.outbox` is written by `history::append` as `change:<seq>`, `DraftChange::Close.notices` and `expire_drafts` notices as `draft:<id>`, in the same transaction; replays and refused writes write nothing. Rows go `pending` → `drained` once (trigger) with a `drained_reason` (`journal`/`stale`/`silent`, 0013); pending rows are never deleted, drained ones only by `prune_model_logs`. `pending_notices` decodes row by row (bad rows come back `undecodable`, never an error); `MemoryScheduleStore::corrupt_notice` mirrors that for tests. `claim_source` dedupes by `DedupeKey::source(source, ordinal)` and stays `Held` unless every attempt under that key was released `NOT_SENT`.
- Reminder card records (`0014`, `sqlite/reminder_cards.rs`, memory `journal.rs`, `journal_conformance`): `reminder_cards` keyed by native dedupe key, written once (`ON CONFLICT DO NOTHING`, never `OR IGNORE`, which would swallow CHECKs; update trigger refuses); `posted_cards(run)` joins bound `reminder` attempts via `delivery_card_runs` (new `run_id` index).
- Run-write observer (`observer.rs`, `RunObserver`): both stores call it after a committed, non-replayed `commit`/`commit_merge` with the runs whose row or RSVPs changed; it runs synchronously, so it must stay a cheap enqueue. `reminder_cards` rows, like the rest of the delivery journal, have no retention path.
- Masked chat (`0015`, `sqlite/model_log/chat.rs`, `record_masked_chat`/`load_masked_chat`): `chat_masked` (PK interaction id → `chat_interactions`, JSON `rounds`/`mapping`, insert-only trigger) holds the admin Model view of a pseudonymized turn, written in the interaction's transaction and pruned with it. `0015` also rebuilds `extractions`/`extraction_members` (children dropped first, new tables renamed) to add outcome `identity_leak`; its indexes and trigger are recreated as before.
- Settings history (`0023`, `sqlite/settings.rs`, memory `settings.rs`, `settings_conformance`): `settings_changes` is append-only (UPDATE/DELETE triggers), one row per effective Config section save with actor, surface, section, revision and a non-empty `{key: {from, to}}` JSON object; `put_settings_rows_recorded` writes it with the section's `config` rows in one `BEGIN IMMEDIATE`, so a refused save records nothing. A Limits window clear is recorded there too (section `limits`, key `window.<member id>`, revision 0, no `config` rows). Not in the hash chain, not revertible, no retention.
- Session avatar (`0025`): nullable `web_sessions.avatar_hash` (32 hex or `a_` + 32 hex, CHECKed on both stores), the Discord avatar a Discord sign-in reported; tests that tamper a store back below v25 must drop it.
- Gateway correlation (`0024`): nullable `chat_interactions.session_id`, `chat_rounds.request_ids`, `extractions.session_id`/`request_ids` (JSON arrays, never `[]`: an empty list is stored NULL and reads back empty); `check_shape` refuses ids outside `[A-Za-z0-9_-]{1,128}` on both stores. Tests that tamper a store back to an older version must drop these columns too.
- Chat outcome `profanity` (`0022`): `chat_interactions` alone is rebuilt under its own name with `PRAGMA defer_foreign_keys` (rows copied aside, table dropped and recreated, rows put back before commit), so `chat_rounds`/`chat_tools`/`chat_masked` keep their schema and references; indexes and the insert-only trigger are recreated as 0007/0008 left them. The detail lives in `guardrail.profanity`.
- Chat turn facts (`0016`): `chat_interactions.persona`/`profile`/`profile_source` (`saved`/`role`/`default`)/`error_code` and `chat_rounds.route` (`homelab`/`external_masked`/`external_unmasked`)/`clean`; nullable or defaulted, so older rows stay valid. `ChatInteraction::check_shape` refuses unknown sources and routes on both stores.
- Token usage (`0019`): `extractions` and `chat_rounds` gain nullable `prompt_tokens`/`completion_tokens` (provider-reported; summed over reporting attempts for an extraction) and `prompt_estimate` (local estimate, independent of the pair); NULL = not reported (older rows, v4 imports, failed calls). CHECKs refuse negatives and a half pair; `ExtractionLog`/`ChatInteraction::check_shape` refuse a half pair on extractions and rounds on both stores, never on `chat_interactions` totals (v4 imports carry half pairs there). The extraction list's body-less variant keeps the usage columns.
- Test cards (`0017`, `sqlite/debug_cards.rs`, journal `claim.rs`/`finalize.rs`, memory `journal.rs`, `journal_conformance`): a `DeliveryTarget::DebugCard` is operation-scoped, never a target row and never held; the claim writes its `debug_cards` row, bind stamps the message and adds `delivery_card_runs`; `clear_debug_card` sets `cleared_at`.
- Journal: claim (lease, target re-check, dedupe) → Discord send outside any transaction → `bind` / `mark_indeterminate` / `release_unsent` / `retire_rejected`; ambiguous sends are never re-claimed.
- Check: `cargo test --all-features --test store` (conformance runs on SQLite and memory; temp dirs only).

# LLM provider guide

- Every model call goes through a governed session (`governor::ModelClient` → `Session`), which drives `execution::CompletionRunner` over the `LlmProvider` trait (`provider.rs`); the runner's constructor is `pub(in crate::infrastructure::llm)` and only test support has `CompletionRunner::ungoverned`. Service code never talks HTTP or a vendor client directly, and there is no native Ollama client.
- Service code obtains completions only through governor sessions; never call `LlmProvider::complete`/`complete_with` directly (that bypasses permits, rate ceiling, retry budget and breaker). Session request counts must stay cancellation-safe: count at admission, not after the await.
- `execution/`: runner, `gate.rs` (per-request admission through the session's permit and request cap), retry/deadline `policy.rs`, encoded-byte and token `accounting.rs`, request/response validation, schema check and quarantine of malformed output. `capabilities/`: per-model capabilities from Kanata `/v1/models` metadata (`listing.rs`), operator declarations or a minimal profile; `downgrade.rs` remembers rejected fields per alias. `shaping.rs` sends only supported fields and embeds the schema instruction when structured output is unsupported. `wire/`: OpenAI JSON types. `http/`: `OpenAiCompatibleProvider` (`config.rs`, `endpoint.rs`, `transport.rs`). `fake.rs`: test-support fake.
- `governor/`: model traffic governor (`config` groups/roles/policy, priority permit `pool`, token-bucket `rate`, retry `budget`, per-group `breaker`, `snapshot` for the Limits DTO, injected `jitter`, `session` question/extraction/rewrite sessions with request caps and charge/refund classification). Pure state takes `now`; waits use tokio time; no wall-clock reads. Routes switch live: `setup::ModelStack::apply_roles` installs every role's alias, resolved effort and zone in one `Governor::reroute` write (`RouteTarget`); a new or unknown alias is external until a listing confirms its zone, joins the group listing it (else the default `gateway` group, else is ungrouped/refused), and sessions, permits and requeues stay pinned to the route they opened with. Ports read `route()` once per call and send its alias and effort. External role calls are governed and send raw prompts without an opt-in; the separate external pre-screen prohibition remains. Check: `cargo test --all-features --test governor`.
- `identity/`: `Member` is the roster data type; `Passthrough`/`PassthroughSession` preserve supplied labels, ids, text, URLs, arguments and results. There is no request pseudonymization, identity scanner, mapping or external-unmasked permission gate. External/unknown routes carry raw data and are logged as `external_unmasked`; retired `models.pseudonymize`, `models.allow_external_unmasked` and their environment variables are rejected by runtime config on presence. `PassthroughSession` is only a small prompt-rendering seam, not a privacy boundary.
- Invariants: capabilities resolved once per runner call and passed via `complete_with`; at most one reshaped retry after a capability rejection; retries only for transient failures (and non-chat timeouts), each behind the governor retry gate with full-jitter backoff; admission refusals only requeue in the session (Kanata error codes pinned to their statuses in `http/mod.rs`); `off` is sent only where allowed (no list, a list with `none`, or no reasoning control), else shaping sends the lowest published level, and alias names are never special-cased; only locally valid values are sent (`wire/check.rs` mirrors Kanata's validation), so only a 400 on a valid sent field downgrades an alias; listing fetch bounded (5 s or half the remaining deadline), cached 300 s, negatively cached 30 s, single-flight.
- HTTP: https with verified roots (webpki-roots or custom); plain http only for loopback IPs, `localhost` (must resolve to loopback) and `host.docker.internal`; no redirects; bodies capped (1 MiB completions, 256 KiB listings, 64 KiB errors); bearer key from caller bytes, redacted in `Debug`/errors.
- `setup/`: builds provider → governor → one `ModelClient` from plain inputs (caller-loaded key bytes, CA path, per-role alias + effort and permits); this layer never reads env or runtime config. Route `external` flags are re-derived from every listing (routes start external); `check_startup` never fails, listing failures only degrade, and each external role gets a raw-data/ZDR-transmission warning. `probe.rs` backs `kanade models check --probe`; its fixed member-free `ping` uses a governed route. Live Kanata verification is still deferred; tests use loopback stubs and the TLS fixtures in `tests/fixtures/provider/`.
- Diagnostics: `Session::last_reservation()` is the last admitted request's token reservation; `Session::refused_reply()` keeps a reply the runner refused for `usage-reservation` (`budget_exceeded`) or as cut off (`incomplete`), for logs only (the rejection is unchanged). An `Incomplete` `LlmError` displays the reply's counts (`Incomplete: reply cut off at the token limit (finish=length, N of M tokens, R reasoning)`), never the provider's finish text. `SessionError::code()` / `ErrorCode::as_str()` are the one code mapping (chat's `AnswerFailure::code` uses them).
- Contract: `docs/notes/provider-contract.md` (update it with behaviour changes). Check: `cargo test --all-features --test provider_contract`.

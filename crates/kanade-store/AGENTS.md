# Store guide

- Crate `kanade-store` (`kanade_store`, sources in `src/`, paths below relative to it): depends only on `kanade-domain`, `kanade-log` and external crates, never on the root `kanade`; the root, its tests and examples import it as `kanade_store::…`. Its `test-support` feature (enabled by the root's) exposes the conformance suites, `TempStoreDir`/`open_temp`, the paused-clock hold and `reader_pool` to other crates' tests.
- `sqlite/` and `order.rs` are production code; `conformance.rs`, `journal_conformance.rs`, `history_conformance.rs`, `draft_conformance.rs`, `precondition_conformance.rs`, `cherry_pick_conformance.rs`, `attendance_conformance.rs`, `model_log_conformance.rs`, `proposal_conformance.rs`, `settings_conformance.rs`, `replay_conformance.rs`, `guides_conformance.rs` and the other `*_conformance.rs` compile only under `cfg(test)` or feature `test-support`. All conformance suites run against SQLite; add new behavioural checks there rather than in backend-specific tests.
- Runtime settings use allowlisted `config` rows (`sqlite/settings.rs`); `v5.profile_visibility` is persisted as an ordered deduplicated list, with a missing row defaulting to empty/private and no schema migration.
- `sqlite/`: `connect.rs` (foreign keys, WAL, `busy_timeout`, `synchronous=FULL` on every connection; reader acquire capped at the same 5 s; `SqliteStore::refuse_reads` fails later reads at once for serve's shutdown cutoff), `migrate.rs` + `migrations/NNNN_*.sql`, `rows.rs` (UTC ISO text timestamps at µs precision, JSON lists), `schedule.rs` (`ScheduleStore`), `writer.rs`, `owner.rs` (ownership), `backup.rs`, `journal/` (`DeliveryJournal`, `CardIndex`), `history.rs`, `drafts.rs` (`DraftStore`: one read txn for `snapshot_with_head`; one `BEGIN IMMEDIATE` per create/update/`commit_merge`/`expire_drafts`; `records_after` maps an unparseable record to `HistoryGap::Tampered`).
- Ownership (`owner.rs`, per `docs/notes/maintenance-contract.md` "v5 store deltas"): `SqliteStoreConfig { db_path, owner_lock_dir }`; paths must be absolute and canonical with no symlinks (macOS: `/private/var`); the lock dir is uid-owned 0700, the DB dir private, the DB file 0600. The DB inode is opened before locking `kanade-{dev:x}-{ino:x}.lock` (no-follow, 0600, one link); a process registry keyed by (dev, inode) refuses second owners; every write transaction, reconnect and backup re-verifies the path still names the owned inode (`IdentityChanged`). `open` and `restore` run in their own tasks so ownership is released only after SQLite closes.
- No SQLite authorizer yet (sqlx exposes no hook): all SQL must stay constant with bound parameters. Adding any caller-influenced SQL requires the deny-by-default authorizer first (release gate). `Backend` error text may contain paths — never surface it to users.
- Commits: `BEGIN IMMEDIATE`, replay a recorded request id (`AlreadyApplied`/`IdempotencyMismatch`), check declared edit preconditions against `change_fields` (`StaleEdit`), then check the store `revision` (`StoreError::Conflict` if stale), collapse puts per key, delete touched keys then insert final rows (UNIQUE can't be deferred), deferred FKs for reminders/RSVPs → runs, bump `revision`. No FK from delivery targets to native rows (bound claims outlive native rows).
- The writer connection is taken out of its slot for each transaction; a cancelled or failed transaction orphans it and the next write reconnects. `close()` is required: it awaits orphans before releasing ownership.
- Test stores (`sqlite/temp.rs`, `sqlite/hold.rs`, test support only): `SqliteStore::open_temp()`/`SqliteCharData::open_temp()` open on a fresh `TempStoreDir` (canonical 0700 dir with `locks/`; `config()`, `raw(sql)`), removed after ownership is released on `close()` or drop, which logs no `store_dropped_unclosed`. A store copies (never hard-links) one migrated template keyed by the migration ledger plus the genesis record, under the private `$TMPDIR/kanade-store-templates/` (~6 ms against ~80 ms migrating from scratch). Every read goes through `SqliteStore::reader()`, never the pool: a reader, a writer lease, open and close each park a `spawn_blocking` task (`ClockHold`) so a paused tokio clock cannot auto-advance while SQLite works on sqlx's threads.
- Test hooks (`sqlite/faults.rs`, test support only) inject commit, card, phrase, mark, and character-link failures: `fail_commit_after(n)` (checked first in `commit_schedule`, so plain and decline-notice commits share the count), `fail_next_card_record_read/write` and `fail_next_digest_phrase_read/write` (counted, one failure per call), `fail_exact_marks(bool)`, and `SqliteCharData::fail_unlinks/fail_put_links(bool)`; each fails before anything is written. `test_map_card_run(msg, run).await` maps a run onto the bound attempt that posted `msg` (panics if none), `test_retire_bound_attempt(&id).await` releases and retires it as actor `test`.
- WAL checkpoint (`maintenance.rs` `StoreMaintenance`, `sqlite/maintenance.rs`): `checkpoint_wal` runs `PRAGMA wal_checkpoint(TRUNCATE)` on a writer lease outside any transaction (the lease is held for that statement only; a cancelled call orphans the connection like a cancelled write) and returns SQLite's `busy`/`log`/`checkpointed`. Serve's retention task calls it after each daily prune, inside the same 60 s run limit.
- Migrations: add `migrations/NNNN_name.sql` and append a `Migration { version, sql: include_str!(..) }` entry to `MIGRATIONS` in `migrate.rs` with the next contiguous version (current: `0001_init` through `0046_cached_tokens`), and pin its checksum in `shipped_migrations_never_change`. v19+: an older image refuses the store (`FutureVersion`); rollback = old image + pre-deploy tarball and rolls back the WHOLE store (schedule, history, delivery journal, drafts, settings), so prefer a forward fix.
- Character roster (`0037`, module `roster`, `sqlite/characters.rs`, `domain::characters::CharacterStore`, `characters_conformance`): `roster_characters` (UNIQUE `(world, ign_key)`, partial unique index one active main per member, no FK). `domain::characters::plan` is the rule set applied before SQLite writes (first active character is the main, a new main demotes the old one in the same write, the main stays while others are active); every write appends one `settings_changes` row (section `characters`, key `character.<id>` per changed row); `ReplayStore::apply_character_replayed` adds the keyed replay (scope `config`) in the same transaction. Not in the hash chain; no retention. Tests that tamper a store back below v37 must `DROP TABLE roster_characters`.
- Run character picks (`0039`, module `roster`, `sqlite/run_picks.rs`, `CharacterStore::run_picks`/`apply_pick`, `run_picks_conformance`): `roster_run_picks` (PK `(run_id, member_id)`, `character_id` FK → `roster_characters` ON DELETE CASCADE, no reference to runs, which commits rewrite). Only explicit picks are stored; `domain::characters::plan_pick` is the rule set applied before SQLite writes (slot version, 0 with no row; an active character of that member; a no-op or refusal writes nothing; a clear deletes the row); every effective write appends one `settings_changes` row (section `characters`, key `pick.<run>.<member>`); `ReplayStore::apply_pick_replayed` adds the keyed replay (scope `config`). `run_picks` binds the run ids as one JSON array (`json_each`), so the SQL stays constant. Not in the hash chain; no retention. Tests that tamper a store back below v39 must `DROP TABLE roster_run_picks` (before `roster_characters`).
- Per-boss picks (`0041`, `sqlite/picks.rs`, `picks_conformance`): `roster_run_boss_picks` / `roster_fixed_boss_picks` (PK `(target, member_id, boss)`, `boss` the catalog boss at any difficulty, `character_id` FK cascade) beside the single picks; `CharacterStore::picks` returns both (single first), `Pick.boss`/`PickChange::{Set,Clear}.boss` name a per-boss slot with its own version, and `PickChange::Same` ("same for every boss", `plan_same`) deletes the named per-boss rows in one write, all or none, with one History row (key `<pick|fixedpick>.<target>.<member>.*`). Per-boss History keys are `….<member>.<boss>`. Tests that tamper a store back below v41 must drop both tables (before `roster_characters`).
- Guides (`0042`, module `guides`, `sqlite/guides.rs`, `domain::guides::GuideStore` (object-safe, boxed futures), `guides_conformance`): `guides` (versioned draft, `blocks` JSON ≤ 64 KiB, partial unique index on `channel_id`), `guide_publishes` (kind `publish`/`unpublish`/`search`, a guide-wide search is a run of kind `search`; partial unique index = one queued/running run per guide, so a second request is `Busy`; a finished run never changes (trigger)), `guide_slots` (PK `(guide_id, channel_id, position)`: during a channel move both sets coexist and an interrupted move keeps the old message ids; `publish_id` → the run that last wrote it), `guide_publish_ops` (kinds incl. `forget`, recorded `pending` then settled once (trigger) with its slot effect in one write; `detail` holds `{"candidates": [message ids]}` from `apply_op_result`'s candidates (an unconfirmed create's search matches), NULL when none, read back as `PublishOp.candidates`). Guide delete is refused `Busy` while a run is queued/running, `Published` while a slot is posted/unknown, else cascades; saves stay open during a run. History (`settings_changes`, section `guides`): `guide.<id>` on create/rename/channel change/delete (sides `{title, channel}`; draft-only saves and no-ops none), `publish.<run>` on request (admin) and on outcome (`system:guides`, surface `delivery_tick`, incl. queued runs stopped `interrupted` on start), `slot.<guide>.<position>` on "Mark as not posted"; refusals record nothing. Keyed forms on `ReplayStore` (`apply_guide_replayed`, `request_publish_replayed`, `request_cancel_replayed`, `mark_not_posted_replayed`, scope `config`), stored only with an effect. Not in the hash chain; no retention. Tests that tamper a store back below v42 must drop `guide_publish_ops`, `guide_slots`, `guide_publishes`, `guides` (in that order).
- Header slots (`0043`) and teasing (`0044`): `reminder_cards.slots` / `header_overrides.slots` (nullable JSON slot map: character, IGN, tease flag, used-estimates) beside the stored heading, which keeps `{cN}` placeholders; only `resolve_heading` fills them at render, else the seed. `members.tease_ok` (0/1) and `members.running_joke` (NULL or 1–80 chars) ride `put_member`/`PortalEdit` and are recorded in the member's change row. Tests that tamper a store back below v43/v44 must drop those columns.
- Members (`0010`, `sqlite/members.rs`, `domain::members::MemberStore`): `members` gains `aliases`/`roles` (JSON arrays), `reply_style` and `is_guild_admin`; `member_aliases` (PK alias) keeps aliases unique across members and is rewritten with the row on every `put_member` (an upsert, never `REPLACE`, which would cascade-delete the aliases). `members_conformance` covers SQLite. Applied versions are SHA-256 checksummed; never edit an applied migration.
- Backups: `VACUUM INTO` a 0700 staging dir, file 0600, published by hard link (never overwrites). `backup_sealed` publishes a `Seal`'s output (age encryption lives in `runtime/backup/`, not here) and deletes the staged plaintext after sealing or with the staging dir on failure. Restore validates the copy first and refuses if the DB or its `-wal`/`-shm`/`-journal` exists. `kanade restore --apply` swaps files under `SqliteStore::hold_for_swap` (current store closed but its inode still owned, the staged copy's inode owned too) and reopens through `SwapOwnership::open`, so no other owner opens the path mid-swap.
- History: every non-empty commit appends a change record in the same transaction (`change_log`, `change_log_weeks`; triggers refuse UPDATE/DELETE); request ids are unique per actor with a stored request digest; verification hashes the stored bytes; backups write `<backup>.manifest.json` with the history head used as an anchor (`open_with_anchor`). Journal writes advance the revision without a record.
- Drafts (`0005`): `drafts`, `draft_ops`, append-only `draft_events`, `draft_requests` (create idempotency per author). CHECKs: `status='merged'` ⇔ `merged_seq` set; a closed status (merged/discarded/rejected/withdrawn/expired) ⇔ `closed_by_*` set (expiry uses the system `delivery` actor). `commit_merge` is one txn: request-id replay → draft live at version (else `Stale`) → revision (`Conflict`) → rows + record + blame + draft merged + event; empty change sets are refused; only `commit_merge` sets merged.
- Attendance (`0006`): standing answers and `attendance_default` live on the fixed-run row (`standing_answers` table written with it), recorded attendance on the run row (`run_attendance`); all three are history-recorded, blamed (`standing:<user>`, `attendance_default`, `attended:<user>`) and returned by `read_versioned`. A hand-set v5 status pin (`Run.status_pin`) is stored in `run_status_pins` with the run row and blamed as the run's `status_pin` field; the change record carries it only when set. `member_history` is one constant `ROW_NUMBER()` query per timing. The service's attendance policy is the single source: calls carrying a mismatching `SchedulePolicy.attendance` are refused (`AttendanceMismatch`).
- Model logs (`0007`, `sqlite/model_log/`, `ModelLogStore`): `messages` (watched cache; an edit with new content clears `processed_at`), insert-only `extractions` + `chat_interactions`/`chat_rounds` (typed outcome CHECKs from `docs/notes/admin-api.md` plus `unknown`; guardrail JSON object; `clean_retry`/`withheld` flags also match those outcome filters), derived filter tables `extraction_members`/`chat_tools`, `rescan_jobs` (final status never changes), `chat_allowance_overrides`, `self_service_tips` (PK member+week; `INSERT OR IGNORE` claim). Filters are one constant query each (`?n IS NULL OR …`, `json_each` for outcome sets), newest first with an `(at, id)` keyset cursor; `q` is ASCII case-insensitive (`instr(lower())`). Because `?n IS NULL OR col = ?n` defeats per-column indexes, lists are bounded scans of the `(at, id)` index (retention bounds the table); the channel-message read uses two constant variants so pending reads hit `messages_unprocessed`. The extraction list has a second constant variant without `prompt`/`raw_response` (`ExtractionFilter::omit_bodies`); a chat page loads its rounds in one `json_each` query; `messages_by_ids` reads by primary key. `mark_read_exact` (extraction's at-most-once mark before effects) checks every row's content then writes in one `BEGIN IMMEDIATE`, all or nothing; a repeated id counts once. `sqlite/model_log/plans.rs` pins the plans with `EXPLAIN QUERY PLAN` and fails on any unused log index (`0008` dropped `chat_member`, `chat_latency`, `extraction_members_member`). Retention (`0008`, user decision: 90 days, `DEFAULT_LOG_RETENTION`): `prune_model_logs(before)` deletes logs with `at < before` (children first) and processed messages created before it, `PRUNE_BATCH` rows per table per `BEGIN IMMEDIATE`, looping until a batch comes back short; logs refuse UPDATE by trigger but allow this DELETE. `store_error` maps trigger `RAISE`s (`SQLITE_CONSTRAINT_TRIGGER`, code 1811, `Other` in sqlx 0.8.6) to `Constraint`.
- Proposals (`0007`, `sqlite/proposals.rs`, `ProposalStore`): an `admin` `drafts` row plus a `draft_proposals` row (triggers: system author + `admin` kind only, never updated/deleted) reads as `DraftKind::Proposal`; create supersedes same-key live proposals (discarded, reason `superseded`) in one txn; TTL expiry by `expires_at`; merges only via `commit_merge`. Proposal cards (`0011`, `sqlite/proposal_cards.rs`, `ProposalCardStore`, `card_conformance`): details written once per proposal (same details again a no-op), bound only by the journal's `card` target (`message_id`/`posted_at`; a trigger refuses other updates and deletes); `0011` also adds `extractions.refusals` (JSON array of `{change, code, message}`). `sqlite/txn.rs` holds the shared `write_txn!`/`read_txn!` macros.
- Notice outbox (`0012`, `sqlite/journal/outbox.rs` + versioned `payload.rs`, `outbox_conformance`): `ChangeMeta.outbox` is written by `history::append` as `change:<seq>`, `DraftChange::Close.notices` and `expire_drafts` notices as `draft:<id>`, in the same transaction; replays and refused writes write nothing. Rows go `pending` → `drained` once (trigger) with a `drained_reason` (`journal`/`stale`/`silent`, 0013); pending rows are never deleted, drained ones only by `prune_model_logs`. `pending_notices_after(after, limit)` reads one keyset page by `id` (write order, served by the partial index `notice_outbox_pending`) and returns `next` only when the page was full; `pending_notices` is the same read unpaged, for checks and inspection only (the drain pages). Both decode row by row (bad rows come back `undecodable`, never an error, and still advance the cursor). `claim_source` dedupes by `DedupeKey::source(source, ordinal)` and stays `Held` unless every attempt under that key was released `NOT_SENT`.
- Reminder card records (`0014`, `sqlite/reminder_cards.rs`, `journal_conformance`): `reminder_cards` keyed by native dedupe key, written once (`ON CONFLICT DO NOTHING`, never `OR IGNORE`, which would swallow CHECKs; update trigger refuses); `posted_cards(run)` joins bound `reminder` attempts via `delivery_card_runs` (new `run_id` index).
- Run-write observer (`observer.rs`, `RunObserver`): the SQLite store calls it after a committed, non-replayed `commit`/`commit_merge` with the runs whose row or RSVPs changed; it runs synchronously, so it must stay a cheap enqueue. `reminder_cards` rows, like the rest of the delivery journal, have no retention path; the one exception is `maintenance_leases`: `prune_leases` (serve's daily retention, cutoff 1 day) deletes ended leases no `delivery_attempts.operation_id` names, in 500-row batches; `0045` indexes live leases so startup recovery doesn't scan.
- Masked chat (`0015`, `sqlite/model_log/chat.rs`, `record_masked_chat`/`load_masked_chat`): `chat_masked` (PK interaction id → `chat_interactions`, JSON `rounds`/`mapping`, insert-only trigger) holds the admin Model view of a pseudonymized turn, written in the interaction's transaction and pruned with it. `0015` also rebuilds `extractions`/`extraction_members` (children dropped first, new tables renamed) to add outcome `identity_leak`; its indexes and trigger are recreated as before.
- Settings history (`0023`, `sqlite/settings.rs`, `settings_conformance`): `settings_changes` is append-only (UPDATE/DELETE triggers), one row per effective Config section save with actor, surface, section, revision and a non-empty `{key: {from, to}}` JSON object; `put_settings_rows_recorded` writes it with the section's `config` rows in one `BEGIN IMMEDIATE`, so a refused save records nothing. A Limits window clear is recorded there too (section `limits`, key `window.<member id>`, revision 0, no `config` rows). Not in the hash chain, not revertible, no retention.
- Rewrites log (`0027`, `sqlite/model_log/rewrites.rs`, `RewriteLogStore`, checks in `model_log_conformance`): insert-only `rewrites` (verdict, kind, stage CHECKs; usage pair all-or-nothing; reply ≤ 8 KiB, reasoning ≤ 64 KiB, `prompt` ≤ 16 KiB (`0029`: the `RewritePrompt` messages under `[system]`/`[user]` labels, NULL when no call was attempted or on older rows)), one `(at, id)` index walked newest first by the constant list query (pinned in `plans.rs`); pages leave out `reasoning_content` and `prompt`. `prune_model_logs` deletes it with the other logs (`PruneCounts.rewrites`); writes hint `Written::Rewrite`. Tests that tamper a store back below v27 must `DROP TABLE rewrites`.
- Header overrides (`0028`, `sqlite/reminder_cards.rs`, `HeaderOverrideStore`, `journal_conformance`): insert-only `header_overrides` (UPDATE/DELETE triggers, no retention) keyed by a reminder card's or digest's native dedupe key, appended by a manual header rewrite; every heading/phrase read (`card_record`, `posted_cards`, `digest_phrase`, the insert-if-absent saves) returns the key's latest override (highest `seq`), else the write-once original, which stays. `0028` also rebuilds `rewrites` for stage `manual` (rows, index and trigger kept). Tests that tamper a store back below v28 must `DROP TABLE header_overrides`.
- Sign-in audit (`0032`, `auth_audit.rs` `AuthAuditStore`, `sqlite/auth_audit.rs`, `auth_audit_conformance`): append-only `auth_audit` (`seq` AUTOINCREMENT, realm/event CHECKs, bounded optional text columns, UPDATE trigger refuses) written by `api::auth::audit::StoreAudit` off the request path (2 s deadline, failure = WARN `audit_unrecorded`); member rows hold only the keyed address tag. `0036` rebuilds it (rows with their `seq`, the `sqlite_sequence` high-water mark, index and trigger kept) to add event `write_refused` (refused member writes: route in `request`, code in `reason`). Each append deletes up to 500 rows older than 90 days before `at` in its transaction; pages are newest-first by `seq` with a `before` keyset cursor. Tests that tamper a store back below v32 must `DROP TABLE auth_audit`. The v4 `audit` table (0001) is unrelated and unused.
- Idempotency replays (`0031`, scope `drafts` since `0038`, `replays.rs` `ReplayStore`, `sqlite/replays.rs`, `replay_conformance`): `idempotency_replays` (PK scope `limits`/`rescan`/`config`/`drafts` + actor + key; 64-hex request digest, 2xx status, JSON body ≤ 16 KiB, `created_at`/`expires_at`, index on `expires_at`) holds the `Idempotency-Key` answers of admin effects that are not scheduler commits (Limits window clear, manual digest and header rewrite, rescan submit/cancel, Config PATCH). `REPLAY_TTL` is 24 h; an expired row reads as absent; there is no scheduled store maintenance, so every replay write deletes the expired rows in its own transaction (`prune_replays` does it on demand). A live row of another request refuses (`Constraint`); the same request may update its answer. `put_settings_rows_replayed` writes settings rows, an optional History record and the replay in one `BEGIN IMMEDIATE`. Tests that tamper a store back below v31 must `DROP TABLE idempotency_replays`.
- Member edits (`ReplayStore::apply_portal_recorded`, `replay_conformance`): one `BEGIN IMMEDIATE` checks the key's live replay first (same request → `PortalWrite::Replayed`, another → `KeyTaken`, nothing written), applies the portal edit, appends a `settings_changes` row (section `members`, key `member.<user id>`, JSON sides of the portal fields, revision 0) only when a field changed, and stores the replay (scope `config`, no migration). Both the admin portal (keyed) and the Discord `/pings`/`/style`/`/nick` commands (`member:<invoker>`, surface `discord`, no replay) write through it; the unrecorded `MemberStore::apply_portal` has no production caller and stays only as the conformance seam for the shared portal-edit rules.
- Composed admin reads (`snapshots.rs` `SnapshotReads`, `sqlite/snapshots.rs`; checks in `history_conformance`/`proposal_conformance`): `history_view` (head, total, run row, page, settings saves, cursor instant) and `inbox_count` read one read transaction. `SqliteStore::pause_next_snapshot_read` (test support) stops the next one after its first statement so a test can commit mid-read.
- Session rotation (`0030`, `web_sessions_conformance`): nullable `web_sessions.client_tag` (64 lowercase hex, a keyed hash of the client address, enforced by SQLite CHECK) and `superseded_until`. `rotate_session` marks the old id superseded and inserts the new one in one write; `load_session`/`touch_session`/`subject_sessions` see live rows only, `load_superseded` returns an old id while `now < superseded_until`. `prune_sessions` and `put_session(replaces)` act on one origin only (admin and public never prune or replace each other's rows); prune also drops superseded rows whose grace is over. Tests that tamper a store back below v30 must drop both columns.
- Session device (`0026`): nullable `web_sessions.device`, a 1–64 character browser/system label derived from the User-Agent at sign-in (the raw header is never stored); tests that tamper a store back below v26 must drop it.
- Session avatar (`0025`): nullable `web_sessions.avatar_hash` (32 hex or `a_` + 32 hex, enforced by SQLite CHECK), the Discord avatar a Discord sign-in reported; tests that tamper a store back below v25 must drop it.
- Gateway correlation (`0024`): nullable `chat_interactions.session_id`, `chat_rounds.request_ids`, `extractions.session_id`/`request_ids` (JSON arrays, never `[]`: an empty list is stored NULL and reads back empty); `check_shape` refuses ids outside `[A-Za-z0-9_-]{1,128}`. Tests that tamper a store back to an older version must drop these columns too.
- Chat outcome `profanity` (`0022`): `chat_interactions` alone is rebuilt under its own name with `PRAGMA defer_foreign_keys` (rows copied aside, table dropped and recreated, rows put back before commit), so `chat_rounds`/`chat_tools`/`chat_masked` keep their schema and references; indexes and the insert-only trigger are recreated as 0007/0008 left them. The detail lives in `guardrail.profanity`.
- Chat turn facts (`0016`): `chat_interactions.persona`/`profile`/`profile_source` (`saved`/`role`/`default`)/`error_code` and `chat_rounds.route` (`homelab`/`external_masked`/`external_unmasked`)/`clean`; nullable or defaulted, so older rows stay valid. `ChatInteraction::check_shape` refuses unknown sources and routes.
- Token usage (`0019`): `extractions` and `chat_rounds` gain nullable `prompt_tokens`/`completion_tokens` (provider-reported; summed over reporting attempts for an extraction) and `prompt_estimate` (local estimate, independent of the pair); NULL = not reported (older rows, v4 imports, failed calls). CHECKs refuse negatives and a half pair; `ExtractionLog`/`ChatInteraction::check_shape` refuse a half pair on extractions and rounds, never on `chat_interactions` totals (v4 imports carry half pairs there). The extraction list's body-less variant keeps the usage columns.
- Cached tokens (`0046`): nullable `cached_tokens` (≥ 0) on `extractions`, `chat_interactions`, `chat_rounds` and `rewrites`: the provider-reported `usage.prompt_tokens_details.cached_tokens`, summed over the attempts/rounds that reported it, NULL when none did (never estimated). `check_shape` refuses a cached count without the usage pair on extractions, rounds and rewrites. Tests that tamper a store back below v46 must drop these columns.
- Test cards (`0017`, `sqlite/debug_cards.rs`, journal `claim.rs`/`finalize.rs`, `journal_conformance`): a `DeliveryTarget::DebugCard` is operation-scoped, never a target row and never held; the claim writes its `debug_cards` row, bind stamps the message and adds `delivery_card_runs` (not for a `sandbox_*` kind, whose run is not checked at claim); `clear_debug_card` sets `cleared_at`.
- Run completion prompts (`0035`, `sqlite/run_prompts.rs`, `domain::completion::RunPromptStore`, `run_prompt_conformance`): one `run_prompts` row per ask (PK run + ask), one open ask per run (partial unique index), closed once (trigger) with the next ask inserted in the same write or not at all; `decided_by` only for pressed outcomes. Not in the hash chain; no retention. Tests that tamper a store back below v35 must `DROP TABLE run_prompts`. The journal's `bound_source(source, ordinal)` returns a bound source-keyed post's receipt (recovers a prompt bound before its message id was recorded).
- Journal: claim (lease, target re-check, dedupe) → Discord send outside any transaction → `bind` / `mark_indeterminate` / `release_unsent` / `retire_rejected`; ambiguous sends are never re-claimed.

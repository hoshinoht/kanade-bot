# Domain guide

- Pure v4-domain port: no I/O, no clock reads, no Discord/SQL/HTTP types. Time and IDs are injected (`scheduler::Clock`, `ids::IdGenerator`). Error `Display` strings match v4 byte-for-byte.
- Crate `kanade-domain` (`kanade_domain`): depends on no other workspace crate; the root `kanade` and the tests import it as `kanade_domain::…`. `spelled!`, `forward_boxed!` and `forward_store!` are `#[macro_export]` (`kanade_domain::spelled!` elsewhere; bare here through `#[macro_use]`). `for_tests` helpers sit behind the `test-support` feature. Items another crate uses are `pub`; keep the rest `pub(crate)`.
- `time/` (`ZonedDateTime`, `AwareDateTime`, `IsoDateTime`): Python `ZoneInfo` semantics — wall clock + zone, `fold` set only by `from_instant`, equality/hash ignore fold, UTC years 1..=9999. `weeks/`: calendar (Monday) vs reset-based boss weeks, fixed-slot placement, weekday/time parsing. `ids.rs`: UUID rows, short tags, prefix resolution. `catalog/`: boss catalog validation/parsing over decoded specs (YAML loading is infrastructure). `pytext.rs`: Python `str` helpers (also used by `kanade-extract` and `kanade-chat`). `members.rs`: `Member`, `Directory`, `Roster`, `PingLevel`.
- `schedule/`: pure planners over `ScheduleSnapshot` → `Draft` → `ChangeSet` (deletes before puts; atomic commit). Models v4 table rules explicitly (duplicate `(run, kind)` reminder is a no-op, rebuild deletes sent rows, past slots written as sent). Mutations emit `Notice` events, not sends.
- `history/`: attribution (`Actor`, `Surface`, `Origin`), the hash-chained change record (`kanade.change.v1` canonical sorted-key JSON, `refs`, golden records in the root's `tests/fixtures/history/golden.json`; any encoder change is a new format version) and pure revert planning (week-scoped restore, forward-only). Contract: `docs/notes/history.md`.
- `scheduler/`: mutations exist only on the per-call handle `service.as_origin(origin).<op>(..)`; a request id makes them idempotent (exact repeat → `AlreadyApplied`, same id with different arguments → `IdempotencyMismatch`); rollbacks (one `rollback` entry over a `RollbackRequest`: by changes, a week to a revision, or an actor since, previewed or applied) reload and re-hash records by seq and emit one notice per affected channel. `SchedulerService` is the single write path (reads the clock once per operation, re-plans up to `COMMIT_ATTEMPTS` on `StoreError::Conflict`); `ports.rs` defines `ScheduleStore`/`Scope`; `store_ref.rs` `StoreRef` forwards the store ports to a borrowed store.
- `proposals/`: extractor/chatbot proposals (v4 `extract/commit.py`): `ProposedChange` → `DraftOp`s on the current snapshot (v4 refusal texts, refused up front), `may_commit`, card notes. The service side is `scheduler/proposals.rs`; merges go through the shared draft merge. Contract: `docs/notes/history.md` *Proposals*. `Approver` fields (`user_id`, `has_role`, `is_admin`) must be derived by the caller from guild permissions and the roster, never from model output or a proposal payload.
- `notify/`: pure notification planning — mention policy, dispatch classification, digest decisions, `Notice` → `NotificationIntent`, the `DeliveryJournal` trait/types in `journal.rs`, and the card ports storage implements: `cards.rs` (`ReminderCardStore`, `DigestPhraseStore`, `HeaderOverrideStore`, `CardRecord`, `PostedCard`, `HeaderSlots`), `debug_cards.rs` (`DebugCardStore`), `card_index.rs` (`CardIndex`, `ReplayCards`; message ids as snowflake text). Planners never send, write or read a clock; execution lives in `src/bot/delivery/` against the journal.
- `settings/`: typed runtime settings and canonical config-row codecs. `v5.profile_visibility` is an ordered deduplicated list; a missing row is empty/private, never inferred from readable persona files. `audit.rs`: `SettingsChange` (a saved section's changed rows, before/after) and `diff_rows`; stores append it with the section's rows (`save_section_recorded`), outside the hash chain.
- `chardata/readiness.rs`: run readiness (pure): each slot's level and power, and its level against each boss's entry level. NEXON values count only from an active link's fresh snapshot (`usable_nexon`), else the manual level and no power; power (NEXON combat power) is shown, never judged. Scouter readings per boss are added by the API from the estimates' memory, never judged either.
- `guides/` (module `guides`): blocks + validation, rendering to Discord payloads (UTF-16 units, refused never clipped; art and knowledge only through `GuideSources`), canonical-JSON slot/plan hashes (pinned; a form change marks every slot out of date), slot planning (`plan`: slot identity `(channel_id, position)`, op order = execution order, exhaustive property tests in `tests/props.rs`) and the object-safe `GuideStore` port. Never imported by chat or extraction (pinned: this crate's tests scan `crates/kanade-chat/src`, `crates/kanade-extract/src` and `crates/kanade-voice/src`, as do the `characters` and `chardata` ones). Contract: `docs/notes/guide-publisher/contract.md`.
- Deliberate v5 deviations from v4 (DST day-of clamp, day-of reconcile keeps a due unsent card of a run still ahead, fixed-edit RSVP drop, home-channel fallback, monotone digest week, `reset_to_fixed`, fixed-edit keep/update choice, attendance status pin and freeze at start, proposals refused up front, proposal TTL at `expires_at <= now`, expired proposals refused) must stay named in tests; anything else keeps v4's behaviour.
- Checks: unit tests are in-module (`#[cfg(test)]`, `cargo test -p kanade-domain --all-features`); integration: `cargo test --all-features --test scheduler|notify` (store parity: `--test store`).

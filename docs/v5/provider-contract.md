# V5 provider contract

`infrastructure::llm::LlmProvider` accepts a model identity and OpenAI-style system, user, assistant and tool messages. Tool calls include an ID, name and JSON arguments; IDs are unique across the complete transcript and returned calls, and each tool result must match a pending call. Requests can include tool input schemas and one strict JSON output schema; responses carry model, content, tool calls, finish reason and optional prompt/completion usage.

The stable offline subset is JSON Schema draft 2020-12 with local `#` references only. `$id`, `$dynamicRef`, `$recursiveRef` and nonlocal `$ref` are rejected before compilation; the maintained validator has resolver features disabled and a rejecting retriever. Value traversal is iterative and bounds schema/output bytes, depth and nodes before compilation. Canonical JSON is counted through a capped writer after preflight, so syntax and escaping count toward schema, request, and response aggregates without allocating an unbounded encoded buffer. The synthetic fixture is `tests/fixtures/provider/structured-response.json`; it is an OpenAI-style shape, not evidence of a Kanata contract.

Defaults: 64 messages, 64 KiB semantic strings and response metadata, 256 KiB output payloads, 32 tools, 512 KiB request/response aggregates, 16,384 tokens, at most three attempts, a 100 ms backoff base and a 30-second total deadline. Construction rejects zero or unbounded limits and policies. Each attempt reserves the conservative estimate (canonical JSON request bytes/4 plus `max_output_tokens`) before calling the provider; this is an offline JSON-accounting seam, not a future HTTP wire-size or provider-tokenizer contract. A transient failure or missing usage consumes the full reservation; reported usage, when present, must fit within it, and a successful response ends the run. A transient failure retries (and an upstream timeout too, except for the chat call kind); authentication, permanent, invalid-output, admission-refused and backend-unavailable failures never do. Before each retry the runner asks the governor's retry gate (breaker and group retry budget), then sleeps a full-jitter pause drawn uniformly below `min(base × 2^(retry − 1), 10 s)` from the governor's injected `Random`; a pause that would pass the deadline ends the call. None of these finish reasons is a successful completion: `content_filter` fails with `ContentFiltered` (user decision: kept apart from a cut-off), while `length` and unknown reasons fail with `Incomplete`. Both are permanent for that request (never retried by the runner) and, since the backend answered, are healthy for the breaker and charged. Kanata passes `length` and `content_filter` through, but an empty filtered or refused reply from Ollama, vLLM or OpenRouter, and any Codex incomplete, reach us as a generic 502 upstream failure, which the runner treats as transient; telling them apart needs a dedicated Kanata error code.

Historical assistant tool calls in the transcript are checked for shape only: non-empty ids unique across the transcript, each paired with exactly one tool result, names matching `[A-Za-z0-9_-]{1,64}`, and arguments that are syntactically valid JSON within the value bounds. They are not checked against `request.tools` or their schemas, so a round may withhold tools (v4's final round and the round after a posted card) after earlier rounds used them, and a lenient chat reply naming an unoffered tool can be resent as history; Kanata checks only name format and non-empty ids on history. Reply tool calls are validated against the tools offered in that request according to `ToolCallValidation`, derived from the call kind (`CallKind::tool_call_validation`): `Strict` for everything except chat, where unknown tools and schema mismatches are `InvalidOutput`; `Lenient` for chat (user decision, v4 parity), where a call naming an unknown or unoffered tool, or with a JSON-object argument the schema rejects, is returned as a normal tool call for the caller to answer with a steering note. Under both, arguments that are not valid JSON or not a JSON object (lenient) or fail the schema (strict), an empty or duplicate id (within the reply or reused from the transcript), an empty name and (lenient) a name outside `[A-Za-z0-9_-]{1,64}` are `InvalidOutput`. Test support adds `CompletionRunner::complete_as(request, kind)`. Malformed JSON, schema mismatches, unknown tools, model mismatches and invalid usage return redacted typed errors carrying only a reason digest. The runner never executes tools, reads environment variables or stores credentials.

`OutputSchema.validation` chooses who judges structured output. `Runner` (the default, omitted from the request's canonical JSON) parses and validates the content as above. `CallerValidates` still sends the schema exactly as `Runner` does (`response_format`, or the schema-in-prompt instruction), and still enforces the content size bounds, but returns the content unparsed and possibly absent; the caller treats it as untrusted text. Extraction uses it because v4's coercions accept near-misses the strict schema would reject, and a malformed answer earns one corrected-answer retry rather than a redacted error.

## Capabilities and request shaping

`ModelCapabilities` holds `operations` (informational), `structured_output`, `sampling_controls`, `reasoning_control`, `function_tools`, `streaming`, an optional `trust_zone` (`local`, `private_network`, `external`), `reasoning_efforts` (`None` means every level is accepted — Kanata sends a list only when a provider restricts levels; Kanata's `none`, `minimal`, `low`, `medium`, `high`, `xhigh` and `max` are all accepted, `none` being our `off`), an informational `context_tokens`, and `admission` — Kanata's private-listener block `{max_in_flight, max_queue, queue_ms, adapter_max_in_flight}` (needs a numeric `max_in_flight`; absent on the public listener and on plain Ollama). `AdmissionLimits::concurrency()` is min(route, adapter) and feeds the governor capacity check; nothing here enforces it. Kanata publishes operation names such as `chat`. Precedence per alias: the `kanata` object of its `GET /v1/models` entry, else operator-declared capabilities (an already-parsed map), else the minimal profile with no response format, sampling, reasoning or tools. The listing parser ignores unknown fields and skips unusable entries; a non-object `kanata` value is absent, and a wrong-typed field keeps its default (`function_tools` true, other flags false). `is_cloud` is an `external` zone or a `-cloud` alias suffix, because Ollama's cloud proxy reports `local`.

`LlmProvider::capabilities(model, deadline)` defaults to `None`, which leaves the request unshaped. The runner resolves capabilities exactly once per `complete` and sends every attempt through `complete_with(request, capabilities)`, so the wire body is built from the same resolution that was shaped and budgeted. With capabilities, the runner shapes before validation and accounting: `off` on a model with reasoning control whose published `reasoning_efforts` list lacks `none` becomes the list's lowest level (the model requires reasoning; user decision 2026-09-26; `capabilities::off_allowed`/`reasoning_floor`); any other reasoning level outside a published `reasoning_efforts` list, or tools for a model without `function_tools`, fails with `UnsupportedCapability` before sending; without `structured_output` the output schema becomes one deterministic system instruction, merged into a leading system message or prepended, and the reply is still validated against the schema (unless the caller validates). That instruction counts toward the content, request and token bounds. The wire body includes `tools`, `response_format` (strict `json_schema`), `max_tokens`/`temperature`/`seed`/`top_p` and `reasoning_effort` only when the corresponding capability allows; `off` is sent as `"none"` (only where allowed, see above; an unshaped body without `none` in the list omits it); Kanata publishes no list when the provider passes every level through, so `None` allows all seven levels. Operator-declared capabilities follow the same rule: an endpoint that rejects `none` needs an explicit `reasoning_efforts` list, or its first `off` request downgrades `reasoning_control` for that alias. Values Kanata would refuse fail locally with `RequestInvalid` before anything is sent, but only for fields actually sent: a `response_format` name outside `[A-Za-z0-9_-]{1,64}`, a non-object schema, a schema over 64 KiB or 32 container levels; `max_tokens` outside 1..=1,048,576; a non-finite or out-of-range (0–2) `temperature`; `top_p` outside (0, 1]; a `seed` above `i64::MAX`; tool or tool-call names outside `[A-Za-z0-9_-]{1,64}`. Always refused: empty system or user content, an empty tool-call id, and an assistant turn with neither text nor tool calls. An empty tool result is sent (and counted) as the placeholder `(no output)`. Because only locally valid values are sent, a 400 naming a sent field is a genuine "unsupported" and downgrades the alias; a local failure never does. In schema-in-prompt mode, one Markdown fence around the whole reply is removed before validation.

## OpenAI-compatible HTTP adapter

`OpenAiCompatibleProvider` sends `POST {base}/v1/chat/completions` and `GET {base}/v1/models` to Kanata or a direct Ollama `/v1` endpoint. The adapter trims one trailing `/v1` and rejects userinfo, queries and empty path segments. It opens one HTTP/1.1 connection per exchange, never follows redirects, and applies one timeout to connect, TLS, request and body. TLS certificate or protocol errors are permanent, while a reset or EOF during the handshake is transient. Body caps are 1 MiB for completions, 256 KiB for listings and 64 KiB for error bodies; the runner's semantic limits still apply. Plain `http` is accepted only for loopback IPs, `localhost` (connected through loopback addresses only) and `host.docker.internal`; any other host is rejected with `HttpConfigError::InsecureHttp`. `https` always verifies certificates using the Rustls `ring` provider installed by `runtime::tls` (construction fails if it is missing). Roots come from the compiled `webpki-roots` set by default, independent of image CA packages, or from a replacement `TrustRoots::Custom` set, such as a private CA. The optional bearer key is caller-loaded secret bytes. It is sent as a sensitive header and never appears in `Debug` or error output.

A 401/403 is an authentication failure (Kanata's `key_expired` 401 surfaces as `ErrorCode::KeyExpired` so operators can tell a rotated-out key); a 504 is `UpstreamTimeout` (a backend phase timed out; Kanata's queue timeout is `503 gateway_busy`), as is the adapter's own exchange timeout and any reply lost after the request was handed to the connection (reset or EOF before the status line, a body cut short after any status line; reason `interrupted`) — the backend may have worked, so it is charged and never retried for chat; a plain 429 with `Retry-After` is `RateLimited {retry_after}` (transient, retried within the retry budget, but the backoff pause is at least `retry_after`; Kanata's own upstream 429 `rate_limit_exceeded` carries no `Retry-After`, so this only fires for direct endpoints); other 429 and 5xx replies are transient; a redirect or other 4xx is permanent. Kanata's codes are read from `error.code`, each only with the status Kanata sends it with: `429 gateway_queue_full`, `503 gateway_busy`, `429 gateway_key_busy` and `429 gateway_key_rate_limited` are `AdmissionRefused {retry_after}`; `503 server_draining` is also an admission refusal (breaker-neutral, requeued after the 1 s default); `503 upstream_unavailable` with `Retry-After` (Kanata's own breaker open) is `BackendUnavailable {retry_after}`, which opens our breaker at once for at least that long (capped at `max_open_cooldown`), while without `Retry-After` (adapter down or unbound) it is transient and counts toward our breaker threshold. `Retry-After` is honoured only as delta-seconds (capped at 3600 s); an HTTP-date is ignored. When a 400 `error.param` names an optional field that was sent (`response_format`, `temperature`, `seed`, `top_p`, `max_tokens` or `reasoning_effort`), the adapter records the downgrade for that alias for its lifetime (thread-safe) and returns `CapabilityRejected`. The runner then reshapes the original request without that capability (for example, adding the schema instruction), revalidates and reserves it again, and sends exactly one more request, whatever the transient attempt count; the rejected attempt keeps its reservation. A second rejection is permanent. Later calls start from the downgraded capabilities. A successful listing is authoritative for `catalog_ttl` (default 300 s), including for unlisted aliases. After that, one fetch is shared by concurrent callers. Each caller's budget is `catalog_timeout` (default 5 s) or half of the runner's remaining deadline, whichever is smaller. A caller that gets no listing falls back to declared or minimal capabilities. Only a fetch that fails, or that exceeds the full `catalog_timeout`, suppresses refetching for `catalog_failure_ttl` (default 30 s); running out of a shorter budget or waiting on another fetch never does. Replies are normalized as follows: a missing `model` echoes the request, a missing tool-call id becomes an unused `call_<index>`, and `stop` with tool calls becomes `tool_calls`. Governed requests carry `x-request-id: {session id}-{n}` (session ids are `kanade-{kind}-{instance}-{sequence}`, always within Kanata's 1–128 `[A-Za-z0-9_-]` rule; `Session::id()` exposes it) through `LlmProvider::complete_tagged`, which defaults to `complete_with`; ungoverned and listing requests send none, and Kanata generates its own. There is no idempotency header (Kanata has none), which is why a lost reply is charged and chat never resends it.

The adapter has been checked only against loopback stubs, including one synthetic self-signed TLS fixture. Env parsing and key-file loading live in `runtime` (see `runtime-bootstrap.md`); verification against the real Kanata gateway (auth and TLS) remains deferred to `integrate-kanata-last`. Direct Ollama normally uses declared capabilities because its listing has no `kanata` object.

## Startup construction

`infrastructure::llm::setup::build(ModelSetup, random)` takes plain inputs — `base_url: Option<String>`, `key: Option<Vec<u8>>` (caller-loaded; redacted in `Debug`), `ca_file: Option<PathBuf>`, `roles: ModelRoles {extraction, chat, rewrite}` (each `RoleModel {alias: Option<String>, effort: RoleEffort}`, `RoleEffort::Level(Effort)` or `Inherit`), `permits`, `allow_external_unmasked` — and returns `Models::Unavailable` when there is no base URL, else `Models::Ready(Box<ModelStack {provider, governor, client}>)`. The base URL is checked by the provider's own endpoint parser (`SetupError::Http`); a bad key, CA file, governor config or an extraction role set to `Inherit` (`ExtractionInherits`) also fails construction. The CA file (PEM bundle, or one DER certificate; ≤ 1 MiB) replaces the compiled roots. All configured aliases share one group `gateway` with `permits` and a rate ceiling of 60 requests/min per permit; a role without an alias has no route (its sessions are refused `UnknownRole`; `has_role` reports it). One `ModelClient` (default execution limits and retry policy) serves every role. `ModelRoles: From<&domain::settings::Models>` maps the stored settings (`extract_model`/`extract_reasoning`, `chat_pilot_model`/`chat_pilot_think`, `v5.rewrite_model`/`v5.rewrite_reasoning`; `""` is `Inherit`).

Trust: a route's `external` flag is derived from the listing with the `ModelInfo.leaves_homelab` rule (`setup::leaves_homelab`, fail closed): only a published `local` or `private_network` zone stays home; `external`, no zone, an unrecognised zone, an unlisted alias, an entry without `kanata` metadata (plain Ollama) and any `-cloud` alias leave. Every route starts external and is re-derived by a listing observer (`OpenAiCompatibleProvider::observe_listings`) on every successful `GET /models` — startup, the runner's own cache refreshes and `ModelStack::spawn_catalog_refresh` (every 300 s, every 30 s until one succeeds; abort the handle on shutdown). A failed listing keeps the last derivation, so a degraded startup keeps every route external until a listing succeeds. `Governor::route` returns the current route by value; `Governor::set_external` updates it. The observer re-derives every route from its *current* alias in one step (`Governor::rederive_external`), so a route switched while a listing lands never takes another alias's zone.

Live role switches (user decision 2026-09-26): `ModelStack::apply_roles` (called by the config API after a models save) is the one writer of the running roles. Under one lock (shared with the listing observer) it resolves every role's alias, effort (inherit, a variant's fixed level and published floors applied, as at startup) and zone (from the cached listing) and installs them in one routes write (`Governor::reroute` with a `RouteTarget` per role), so no call sees a new alias with the old effort or zone. Ports read `Governor::route` once per call (chat: once per question, when it is prepared, then `ModelClient::open_question_on` takes the permit on that same route) and send its alias and effort, so the next question, extraction or rewrite uses them; a session keeps its permit's alias and group, and a slot-loss requeue returns to that same alias and group even if the role moved. A switched-to alias: starts `external` (fail closed: masked with pseudonymization on, refused without it unless the unmasked override is set) until a listing — the cached one counts — shows its zone; takes the declared group that lists it; with no declared groups joins the default `gateway` group (created on first use, `KANADE_MODEL_PERMITS`), whose alias list then follows the routed aliases; with declared groups and no listing group it is ungrouped and its calls are refused, as at startup (the config API refuses such a save first). Capability cache entries and downgrade memory are per alias, so a new alias starts with none. An alias `None` unroutes the role (its sessions are `UnknownRole`). Pseudonymization codecs and scan exemptions are per role (chat's include the route alias read per question), so they follow a switch. Startup warnings (`Governor::warnings`) are not recomputed.

Reasoning (`ModelStack::efforts()`/`effort(role)`): `Inherit` takes the extraction role's configured level. The level is checked against the role's own alias: `off` needs no published list, a list containing `none`, or no `reasoning_control` (nothing is sent); any other level must be in a published list (`check_reasoning_effort`; `null` allows every level). A stranded level — including `off` on a model that requires reasoning — is replaced by `off` where that is allowed, else by the alias's lowest published level, and reported (`EffortStatus.stranded`); no alias names are special-cased; without a listing, or for an alias with nothing published, the configured level is kept (the runner still refuses per call). `ModelStack::catalog()` is the read-only `CatalogSnapshot {listed, models: [CatalogModel {alias, published, trust_zone, leaves_homelab, reasoning_control, reasoning_efforts, structured_output, sampling_controls, function_tools, context_tokens, admission}]}` of the last successful listing (serializable, for the config API); `CatalogModel::off_allowed()`/`reasoning_floor()` apply the rule above (A9 exposes `ModelInfo.off_allowed`). `setup::variant_of`/`CatalogSnapshot::variant` detect `<base>:<level>` variants (a known effort suffix on a listed base; admin-api.md "Config semantics"); a role on a variant uses its fixed level (inheritors of extraction too), then the checks above against the variant's own capabilities.

`ModelStack::check_startup()` never fails. It lists models once (bounded 5 s); a failure or timeout returns `Listing::Degraded {reason_code}`. It reports `StartupWarning`s: governor warnings, with a listing also `PermitsAboveGateway` and `UnpublishedEffort {role, alias, effort, sent}` (`sent` is the fallback level actually used), and for each external route `ExternalRefused {role, alias}` or, with the override, `ExternalUnmasked {role, alias}` (its `Display` starts `UNMASKED:`). The layer does not log: the caller logs the report.

`ModelStack::probe(role, codec, timeout)` (for `kanade models check --probe`) sends one completion with a fixed prompt and no member data (`max_tokens` 128, the role's effective effort, no tools or schema) through the role's own session kind (extraction, admin question, try-only rewrite; a rewrite refused only by an empty rate bucket waits out the refill once) after the route guard, with the boundary scanner of an empty-roster grant (`open_session(codec, route, [])`) attached, and returns `ProbeOutcome::Ok {latency_ms, finish_reason}`, `Refused` (nothing sent) or `Failed`.

## Identity codec

`infrastructure::llm::identity` is the seam every extraction and chat prompt goes through (pseudonymization stage 1). An `IdentityCodec` reports its `CodecMode` and opens an `IdentitySession` over the roster (`Member {user_id, display_name, nickname, aliases}`; `Debug` shows counts only): extraction opens one per request, chat one per question (all of its tool rounds), and mappings never outlive the session. Sessions encode author labels (`author_label(user_id, name)`), member refs for participant lists, extractor `participants` and tool arguments (`member_ref`, `participants`), mentions (`<@{member_ref}>`), free text and tool results; `participant_enum()` returns the refs issued so far for a strict schema enum (`None` = unconstrained); `decode_ref`, `decode_json` (tool arguments, structured output) and `decode_reply` map model output back, failing with `DecodeError::UnknownToken` (callers quarantine as malformed); `scan_needles()` (default `None`) returns what the session masks for a boundary scanner. Mapping state lives only in the session and is never persisted.

`Passthrough` is the default: every encode and decode returns its input unchanged (labels are the Discord name, refs the decimal user id, `participant_enum` is `None`), so a request built through it is byte-identical to one built without a codec. Ports open sessions through `open_session(codec, route, roster)`, which runs `guard` on every call and returns an `IdentityGrant` (derefs to the session; `scanner()` is its boundary scanner, see below): a `RoleRoute` marked `external` is refused (`RouteRefused::ExternalWithoutPseudonymization`) while the codec is passthrough, unless the route carries `unmasked_allowed` (the governor-wide operator override `Governor::allow_external_unmasked`, from `KANADE_ALLOW_EXTERNAL_UNMASKED=1`; default off). `identity::unmasked(route, codec)` is true when member data goes out in plain text; extraction and chat then add `"external_unmasked": true` to the model-log row's `guardrail`. `check_routes` applies the same guard to all routes at startup. The guard reads only the route's `external` marker (derived from the listing, see Startup construction), not `ModelCapabilities::is_cloud`. The on mode is `PseudonymCodec` (below), composed by serve for every role when `models.pseudonymize` / `KANADE_PSEUDONYMIZE` is on (then masking wins over the unmasked override: external routes run masked, and startup warns `override_unused` if the override is set too). Test support adds `TaggingCodec` (sequential `ID<n>` tags, reports `Pseudonymizing`) and `find_leaks`/`find_request_leaks`, which list roster names, nicknames, aliases, roster ids and snowflake-length digit runs in captured requests.

`PseudonymCodec::new(PseudonymConfig {pool, lexicon, bot, extra_exclusions, random})` (reports `Pseudonymizing`) replaces identities with fictional given names. Tokens come from `NamePool::curated()`, the tracked list `src/infrastructure/llm/identity/pseudonym/names.txt` (about 300 romanized Japanese given names; 3+ ASCII letters, capitalised, none ending in `s`), drawn uniformly without replacement from the injected `governor::Random` (`SystemRng`, i.e. ring's OS source, in production; seeded `XorShift` in tests) when an identity is first needed, so assignments are per-session and unlinkable (never sequential or hashed). Filtering uses a normalisation (lowercase, letters/digits only, macron vowels and long vowels `ou`/`oo`→`o`, `uu`→`u`, doubled vowels folded) and a near-match rule: equal, containment (the contained side at least 3 characters) or, both at least 3 characters, one edit apart. At construction the pool drops names near a `CodeLexicon` term (`builtin()`: weekdays/months and abbreviations, difficulty words, `p1`–`p4`, MapleStory classes, NPCs and bosses, schema words; `from_boss_table` adds the loaded catalog's shorts, full names, aliases, canonical forms and difficulty labels), near the bot name, persona names (`BotIdentity.aliases`) or `extra_exclusions`, or equal to an English stopword. At session open (and whenever `author_label` adds a name) it drops names near any roster display name, nickname, alias or author name and each of their words. Any pool form found in text being encoded is never issued in that session and decodes literally; a source word spelling an already issued token is shadowed by a fresh token that decodes back to that literal text. When the filtered pool runs out, tokens continue deterministically as `<Name><n>` (filtered pool in list order, n = 2, 3, …); if every pool name was excluded, `Nanashi<n>` (a numbered `Nanashi` in source is a pool form too, so it stays literal).

Encoding (`text`, `tool_result`) runs, at each position: the position after a possible backslash escape (`\n`, `\t`, `\r`, `\b`, `\f`, `\uXXXX`, whether or not the backslash is itself escaped) counts as a word boundary, and so does the letter right after any backslash, so both `\nBob` and a stray-backslash `C:\bobby` are masked; `<@id>`/`<@!id>` → `<@Token>` for any id; `http(s)://` URLs (ending at whitespace, `<`, `>`, `"`, a backtick or a backslash) are copied except digit runs equal to a known id, which become tokens; the longest matching needle (display name, nickname, aliases, author labels, plus each without leading/trailing decoration such as emoji), Unicode lowercase-insensitive and whole-word (a match may not split two word chars, except next to kana, CJK ideographs or Thai, which are written without spaces); needles under 2 characters are skipped and counted; a maximal ASCII digit run equal to a roster id or an issued id → token. Other 17–20 digit runs become opaque `Ref<n>` tokens, and `<#channel>`/`<@&role>` render as names where the guild cache knows them (below). `member_ref`, `author_label` and `mention` issue a token for any user id, roster or not, and every `author_label` name becomes a needle for text encoded afterwards, so ports must register every author (`author_label`) before encoding text that may mention them. A `tool_result` that is a JSON object or array is encoded structurally: each string literal (keys included) is unescaped (lone surrogate escapes read as U+FFFD), encoded and re-escaped only if it changed, and an integer equal to a known id becomes its token as a JSON string; other bytes are kept. Other content goes through `text` rules. The bot (`BotIdentity.user_id`) is never tokenised: its label and ref are its name, its mention and a raw `<@bot>` are `@name`, its bare id becomes its name, and `decode_ref(name)` returns its id. Member names equal to a lexicon term or stopword (a member called `Sun` or `Will`) are masked anyway in member text; code-owned text is never passed through a session, so it stays literal. `participant_enum` is exactly the member tokens issued so far, in issue order. Decoding copies possible backslash escapes whole (so a model writing `\tomoe` lowercase right after a backslash is not decoded) and matches word runs, split where a Latin letter meets kana, CJK or Thai (so `Tokenさん` decodes), case-insensitively against the ASCII tokens; strips one trailing `s` (`Token`, `token`, `Token's`, `Tokens'`, `<@Token>`), maps a token to the user id in `decode_ref`/`decode_json` and to the member's display name (else the last author label, else `someone`) in `decode_reply`, where `<@Token>` loses its brackets; a pool form the session neither issued nor saw in source is `UnknownToken` in all three (replies are quarantined too). `scan_needles()` returns `ScanNeedles {names: [ScanName {text, collides, token_clash}], ids, tokens, skipped_short}`, where `collides` flags names equal to a lexicon term or stopword, `tokens` lists every issued token and `token_clash` flags a name that equals or near-matches one (an author registered after that token was issued; its later text still maps to its own token). `Debug` on the codec, config, pool, lexicon, bot, session and needles prints counts only; nothing is logged or written. Residuals for the boundary scanner: names inside URLs, single-character names, names spelled with escapes in non-JSON text (`\u0042ob`), a lowercase token written right after a backslash in model output, names split by a mid-name backslash, decomposed Unicode (no NFC), words of multi-word names shorter than three characters, English stopwords or code-lexicon terms (`tan` of `Alice Tan`, `Will` of `Will Smith`), non-roster nicknames (a party channel named after someone the roster does not list), known names inside URL paths (URLs are never rewritten: `github.com/hoshinoht/…` in persona text keeps `hoshinoht`), and names in text encoded before their author was registered.

Word needles (live finding: party channels are named after members' first names). Every word of a multi-word display name, nickname, alias, author label or former name is also a needle for the same member when it has at least three characters and is neither an English stopword nor a code-lexicon term (`CodeLexicon::collides`), so `jonas` of `Jonas lau` becomes Jonas lau's token in text, channel names and tool results, and decodes back to the display name. Longest match still wins (`Jonas lau` is one token), and at equal length a whole name (display name, nickname, alias, author label, former name) outranks a word, so `Alex` is the member called Alex, never `Alex Tan`. No word needle is created that equals any member's whole name (a whole name registered later removes it). A word two or more members share (`Lim` of `Kevin Lim` and `Sarah Lim`) is still masked and scanned but belongs to nobody: its token is not a participant (`participant_enum`, `mapping` leave it out), `decode_ref`/`decode_json` refuse it as `UnknownToken`, and `decode_reply` shows the word as written. A word that becomes shared mid-session (an author registered later) stands for nobody from then on; text encoded earlier keeps the member it was encoded for, never re-attributed. Words equal to the bot's name or aliases or a persona name (`extra_exclusions`) are never word needles, so a member called `Kanade Fan` cannot mask the persona's own name. Two-letter words (`Li`, `Ng`) are not word needles: they would mask ordinary text and abbreviations. Pool names are not excluded: a member named `Yuto Tanaka` must not leak `Yuto`, and the session already withdraws near pool names from issuance, so no token can equal the word. Privacy over availability (user preference): common surnames of three letters or more (`lau`, `lim`) are masked wherever they appear. `_` and `-` separate words (`hstar-jonas_lau`), for needles, decoding and the scanner alike.

Boundary scanner. For a `Pseudonymizing` codec the grant's `LeakScanner` shares the session (behind a mutex), so it reads `scan_needles()` at scan time and covers author labels registered mid-session; for `Passthrough` it is off and requests are unscanned and byte-identical. Ports attach it with `Session::with_scanner(grant.scanner())` (chat question, extraction, rewrite, probe). A client built with pseudonymization on (`ModelClient::with_masking(true)`, from `ModelSetup::pseudonymize`) fails closed: a session with no active scanner refuses every request as `unscannable`, so a port that forgets to attach one sends nothing. The runner scans the exact (shaped) `ChatRequest` of every attempt at the top of its loop, before the token reservation and gate admission, so first requests, reshaped and transient retries, requeues, clean and answer retries are all scanned and a refusal spends no request cap, rate token or retry budget. Only content is scanned: message text, tool-call names and arguments, tool results, tool definitions and output schemas (every key, string and number); fixed structure (the model alias, roles, token limits, reasoning, sampling, `strict`, validation) never is. Tool arguments and results that parse as a JSON object or array are walked structurally (every unescaped key and string), so `\u0041lice` cannot hide a name. Model-issued call ids (`ToolCallRequest.id`, `tool_call_id`) get known-id matching only, never the snowflake rule. An assistant turn whose text or tool arguments equal something the model itself wrote in this session (the runner records every validated reply) is not scanned: echoing the model's own words discloses nothing, and a model saying "will" must not refuse a member `Will`. Names use the codec's matching (whole-word, Unicode lowercase-insensitive, longest first, a possible backslash escape is a boundary); a maximal ASCII digit run (not preceded by a digit) equal to a roster or issued id is `id`, any other 17–20 digit run is `snowflake` (the codec turns stray snowflakes and extraction message ids into refs first). A name match whose text is exactly an issued token (a `token_clash` author named like an earlier token) is not a leak; the scanner relies on encoding for that name. A session that reports no needles fails closed (`unscannable`). Tailored exemptions (user decision): a masked name is skipped only when every word of it occurs in code-owned prompt text, held as `ScanExemptions` (whole words, Unicode lowercase). `ScanExemptions::builtin()` holds only what the runner itself adds (its schema instruction and empty-tool-result placeholder); `PseudonymCodec` adds the bot's name and aliases (never masked); each role's real sources supply the rest through `with_texts`/`with_value`/`with_boss_table` and `PseudonymCodec::with_scan_exemptions` (serve: `runtime::serve::privacy`; chat: its policies, cues, clock header with weekday and month names and the zone, runtime line, focus words, tool definitions and the boss catalog; extraction: the system prompt, user-prompt headings, weekday names, retry instruction, schema and BOSSES table; rewrite: its instruction, moods and voice label). The broad `collides` flag is not used: members called `Ken` or `Max` are always scanned, one called `Will` is skipped only where that role's code text says "will". A hit is `SessionFailure::IdentityLeakBlocked(IdentityLeakBlocked {role, kinds, count})` (kinds `name`, `id`, `snowflake`, `unscannable`), always `Refunded`, never retried or requeued, not a misconfiguration; `payload()` is `{role, kinds, count}` and `log_line()` the WARN `identity_leak_blocked` line; neither they, `Display` nor `Debug` ever includes the matched text. Scanner residuals: the codec residuals it shares (names split by a mid-name backslash, `\u`-escaped in non-JSON text, decomposed, single-character, words of multi-word names that are not word needles, non-roster nicknames, and known names inside URL paths), an unmasked name whose every word is an exempt code-owned word of that role (a member called `Will` or `Carling` written raw), an unmasked name spelled exactly like an issued token, raw bot and persona names, and a raw name inside the model's own echoed words.

Wire-ports codec additions. `IdentitySession::masks()` says whether a session hides identities; `message_ref(id)` renders an extraction message id as a short per-session ref (`1`, `2`, …; the id itself in passthrough) and `decode_message_ref` maps it back (unknown refs are `UnknownToken`); `mapping()` lists the issued member tokens with their user id and display name at the time (the admin Model view; never logged; `IssuedName`'s `Debug` shows sizes). `PseudonymCodec::with_mention_names(MentionNames)` renders `<#id>` as `#name` and `<@&id>` as `@name` (the name encoded as text); any other 17–20 digit run of nobody in the session, in text, URLs, mentions or tool-result JSON, becomes an opaque `Ref<n>` that decodes back to its digits (a `Ref<n>` spelled in source text stays literal and is never issued). `encode_protected(session, text, &[Protected])` copies code-owned pieces (`Exact` text, or a `Span` from a start marker through an end marker) verbatim and encodes only the gaps; passthrough output equals the input. `RosterSource` is a port's per-call roster (`None` when unreadable). `former_name(user_id, name)` registers a name a member was known by before (renamed, removed alias, left the roster) as a needle without issuing a token, so stored text rendered with it is masked and the scanner knows it.

## Model traffic governor

`infrastructure::llm::governor::Governor` is the single admission point for model traffic (chat, extraction, rescans, follow-ups, rewrites, pre-screen). Completions are obtained only through governed sessions: `CompletionRunner` has no public constructor or call outside feature `test-support` (whose `ungoverned` runner exists for provider contract tests).

Configuration: backend capacity groups `{name, backend, permits 1..=64, requests_per_min 1..=6000, burst 1..=1000 (default = permits), aliases}`; an alias belongs to exactly one group. Roles (`extraction`, `chat`, `rewrite`) map to `{alias, external}` and resolve to their alias's group. Validation refuses (first error, naming the group or role) out-of-range numbers, duplicate groups or aliases, empty names and policy values out of range. A role whose alias is in no group only warns; its calls are refused (`Ungrouped`), never run ungoverned. Once the gateway listing is known, `GovernorConfig::capacity_warnings(published)` (or `Governor::new_checked`) adds `PermitsAboveGateway {group, alias, permits, gateway}` for each alias whose published `admission.concurrency()` is below its group's permits; aliases with nothing published are not checked there (operator-declared limits are validated by the config API), and per-key limits are never published by Kanata, so they stay operator-declared. Policy defaults: breaker threshold 5, cooldown 30 s doubling per consecutive trip up to 300 s, drain step 5 s, retry budget 150‰ with a floor of 1 per 60 s window (permille ≤ 200).

- Permits: one permit covers a whole interaction. `acquire(role, ticket, wait)` queues by class — admin > in-flight chat rounds > new chat > extraction > follow-ups — FIFO within a class; it times out after `wait`, and dropping the future leaves the queue (or returns a permit granted in the same instant). While the breaker is open it is refused at once. Rewrite and pre-screen kinds may only `try_acquire`, which never waits, never jumps a queued waiter, and refuses pre-screen on an `external` route. It is refused while the breaker is open or a probe is in flight; half-open with no probe in flight it may take the single slot, and that holder's first request becomes the probe, so a group reached only through `try_acquire` (such as rewrite) still recovers. Dropping a `Permit` hands it to the next waiter.
- Requests: every provider request is admitted through its permit. `begin_request(max_wait)` checks the breaker, then takes a token-bucket token (`requests_per_min` refill, `burst` depth); tokens are reserved in order, so a caller waits its turn, and a wait longer than `max_wait` is refused without taking a token. The request (and any retry-budget spend) is recorded only once the wait ends and the breaker is re-checked; a request refused after its wait, or cancelled during it, refunds its token (capped at the burst) and records nothing, and a cancelled probe frees the probe slot. `try_begin_request` never waits. `begin_retry` additionally spends the group's retry budget: retries in the sliding window stay ≤ max(floor, permille × first attempts); retries do not count as requests. The caller reports each `Attempt` with `finish(outcome)`.
- Breaker per group: success or a permanent rejection resets the consecutive-failure count; transient failures and timeouts count toward the threshold; backend-unavailable opens at once (`Outcome::BackendUnavailableFor(d)` keeps it open at least `d`, capped at `max_open_cooldown`, so we never probe while the gateway's breaker is still open); admission refusals are neutral. Open refuses new work with `Unavailable {retry_at}` until the jittered probe time (cooldown × [1, 1.5), applied after the 300 s cap, so at most about 450 s), then half-open admits exactly one probe request (an abandoned or admission-refused probe frees the slot). A healthy probe closes the breaker and permits come back one per drain step, so queued work drains gradually alongside the rate ceiling; a failed probe reopens with a doubled cooldown. Outcomes of requests started before a trip are ignored while open.
- Time is tokio's clock (paused in tests); jitter comes from an injected `Random`; `snapshot(wall_now)` maps instants onto the caller's wall clock and returns per group the `BackendGroup` DTO fields of `docs/v5/limits-contract.md` (permits, dense 1-based queue with kind/who/waiting_s, rate level, retry remaining/capacity, breaker state/failures/since/retry_at — `retry_at` only while open) plus holders and cumulative counters (requests, retries, outcomes, sheds).
- Sessions: `ModelClient::new(governor, provider, limits, retry)` opens them; backoff jitter uses the governor's `Random`. Every provider request of a session (first attempts, transient retries, capability reshapes, requeues) passes `begin_request`/`begin_retry` on the session's permit, reports its outcome (success or a permanent rejection is healthy, transient/timeout count toward the breaker, backend-unavailable opens it, admission refusals are neutral; a request cut off by our own deadline is abandoned, i.e. neutral) and counts toward the session's request cap the moment it is admitted, so a `complete`/`clean_retry`/`answer_retry` future dropped mid-request (timeout, `select!`) still spends its request, a cancelled clean or answer retry still uses the reserved one, and an extraction call is marked started before it awaits, so a cancelled one cannot be repeated or retried. Requests must name the permit's alias; chat, extraction and rewrite build theirs (alias and effort) from the route they checked, so a switch between that check and the permit fails as `session-alias` rather than reaching a route the identity guard never saw; chat avoids even that by taking its permit on the checked route (`open_question_on`, `Governor::acquire_route`: that route's alias and group).
  - `open_question(who, admin, QuestionLimits {tool_rounds 1..=12 (default 8), timeout})` queues in the admin or new-chat class within the timeout, which bounds the whole question. One permit is held across all tool rounds. `max_requests` = tool rounds + 1 (user decision Q2: default 9); `complete` may use all but one, which stays reserved for `clean_retry` — at most once, only while the breaker is closed and retry budget remains, spending that budget. Transient retries, reshapes and the requeue all draw from the same cap and deadline.
  - Slot loss: an `AdmissionRefused` reply is never retried directly. The session gives its permit back, waits `Retry-After` (1 s if absent, at least 250 ms) plus full jitter over the same span, requeues in the in-flight chat class (admins stay admin) and resends as a retry (spending retry budget) — exactly once per session, and only if the pause fits before the deadline, a request remains and the retry gate (breaker, retry budget) admits it; that gate is asked while the permit is still held, so a retry that could not happen fails at once (refunded) without releasing the slot. A clean retry skipped because the breaker is half-open is not counted as shed work. A timeout (504, transport, lost reply or deadline mid-request) is charged and ends the question; later calls fail with `Ended`.
  - `open_extraction(who, wait, timeout)` is a session at extraction priority: one `complete`, then at most one `answer_retry` (the caller rejected the reply it returned; v4's corrected-answer request) within the same permit. `max_requests` = the runner's attempts + 1 reshape + 1 reserved for the answer retry, which `complete` cannot use. The answer retry is a content retry: it counts toward the cap and deadline and is admitted like a first request (breaker and rate), not through the retry gate, so it spends no group retry budget; its own transient retries do. It is refused (`AnswerRetryUnavailable`) before a reply, after a failed or cancelled `complete`, or once used. Non-chat kinds may retry an upstream timeout within the retry budget.
  - `open_rewrite(who, timeout)` (nudge rewrites; not async) never waits: the `rewrite` role's permit comes from `try_acquire` and its rate token from `try_begin_request`, so a busy group, open breaker, in-flight probe or empty bucket is refused at once with nothing sent. `max_requests` = 1 and one `complete`: no transport retry, reshape, requeue or answer retry; `timeout` (1 ms..=300 s) bounds the request. Callers open the identity session through `open_session` like any other port (passthrough refuses `external` routes). In general, try-only kinds (rewrite, pre-screen) never wait for a rate token and are never admitted as retries.
  - `Refused::is_misconfiguration()` / `SessionError::is_misconfiguration()` split failures that need an operator or a code change (unknown or ungrouped role, route guard, `MustNotWait`, invalid request, unsupported capability, authentication, expired key, model mismatch) from "unavailable now" (busy, queue timeout, breaker, rate ceiling, retry budget, model failures).
  - Failures are `SessionError {failure, charge}`: `Refused` (governor), `RequestsExhausted`, `Ended`, `CleanRetryUnavailable`, `AnswerRetryUnavailable`, `IdentityLeakBlocked` (boundary scanner, always refunded) or `Model(LlmError)`, each `Charged` or `Refunded` for the chat allowance. Charged means the backend produced a reply (invalid output, incomplete finish, content filter, model or usage mismatch included) or may still be working (any timeout); governor refusals, admission refusals, backend-unavailable, transient and permanent failures and local validation are refunded. New `ErrorCode`s: `AdmissionRefused`, `BackendUnavailable`, `UpstreamTimeout`.

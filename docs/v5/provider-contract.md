# V5 provider contract

`infrastructure::llm::LlmProvider` accepts a model identity and OpenAI-style system, user, assistant and tool messages. Tool calls include an ID, name and JSON arguments; IDs are unique across the complete transcript and returned calls, and each tool result must match a pending call. Requests can include tool input schemas and one strict JSON output schema; responses carry model, content, tool calls, finish reason and optional prompt/completion usage.

The stable offline subset is JSON Schema draft 2020-12 with local `#` references only. `$id`, `$dynamicRef`, `$recursiveRef` and nonlocal `$ref` are rejected before compilation; the maintained validator has resolver features disabled and a rejecting retriever. Value traversal is iterative and bounds schema/output bytes, depth and nodes before compilation. Canonical JSON is counted through a capped writer after preflight, so syntax and escaping count toward schema, request, and response aggregates without allocating an unbounded encoded buffer. The synthetic fixture is `tests/fixtures/provider/structured-response.json`; it is an OpenAI-style shape, not evidence of a Kanata contract.

Defaults: 64 messages, 64 KiB semantic strings and response metadata, 256 KiB output payloads, 32 tools, 512 KiB request/response aggregates, 16,384 tokens, at most three attempts, a 100 ms backoff base and a 30-second total deadline. Construction rejects zero or unbounded limits and policies. Each attempt reserves the conservative estimate (canonical JSON request bytes/4 plus `max_output_tokens`) before calling the provider; this is an offline JSON-accounting seam, not a future HTTP wire-size or provider-tokenizer contract. A transient failure or missing usage consumes the full reservation; reported usage, when present, must fit within it, and a successful response ends the run. A transient failure retries (and an upstream timeout too, except for the chat call kind); authentication, permanent, invalid-output, admission-refused and backend-unavailable failures never do. Before each retry the runner asks the governor's retry gate (breaker and group retry budget), then sleeps a full-jitter pause drawn uniformly below `min(base × 2^(retry − 1), 10 s)` from the governor's injected `Random`; a pause that would pass the deadline ends the call. None of these finish reasons is a successful completion: `content_filter` fails with `ContentFiltered` (user decision: kept apart from a cut-off), while `length` and unknown reasons fail with `Incomplete`. Both are permanent for that request (never retried by the runner) and, since the backend answered, are healthy for the breaker and charged. Kanata passes `length` and `content_filter` through, but an empty filtered or refused reply from Ollama, vLLM or OpenRouter, and any Codex incomplete, reach us as a generic 502 upstream failure, which the runner treats as transient; telling them apart needs a dedicated Kanata error code.

Historical assistant tool calls in the transcript are checked for shape only: non-empty ids unique across the transcript, each paired with exactly one tool result, names matching `[A-Za-z0-9_-]{1,64}`, and arguments that are syntactically valid JSON within the value bounds. They are not checked against `request.tools` or their schemas, so a round may withhold tools (v4's final round and the round after a posted card) after earlier rounds used them, and a lenient chat reply naming an unoffered tool can be resent as history; Kanata checks only name format and non-empty ids on history. Reply tool calls are validated against the tools offered in that request according to `ToolCallValidation`, derived from the call kind (`CallKind::tool_call_validation`): `Strict` for everything except chat, where unknown tools and schema mismatches are `InvalidOutput`; `Lenient` for chat (user decision, v4 parity), where a call naming an unknown or unoffered tool, or with a JSON-object argument the schema rejects, is returned as a normal tool call for the caller to answer with a steering note. Under both, arguments that are not valid JSON or not a JSON object (lenient) or fail the schema (strict), an empty or duplicate id (within the reply or reused from the transcript), an empty name and (lenient) a name outside `[A-Za-z0-9_-]{1,64}` are `InvalidOutput`. Test support adds `CompletionRunner::complete_as(request, kind)`. Malformed JSON, schema mismatches, unknown tools, model mismatches and invalid usage return redacted typed errors carrying only a reason digest. The runner never executes tools, reads environment variables or stores credentials.

`OutputSchema.validation` chooses who judges structured output. `Runner` (the default, omitted from the request's canonical JSON) parses and validates the content as above. `CallerValidates` still sends the schema exactly as `Runner` does (`response_format`, or the schema-in-prompt instruction), and still enforces the content size bounds, but returns the content unparsed and possibly absent; the caller treats it as untrusted text. Extraction uses it because v4's coercions accept near-misses the strict schema would reject, and a malformed answer earns one corrected-answer retry rather than a redacted error.

## Capabilities and request shaping

`ModelCapabilities` holds `operations` (informational), `structured_output`, `sampling_controls`, `reasoning_control`, `function_tools`, `streaming`, an optional `trust_zone` (`local`, `private_network`, `external`), `reasoning_efforts` (`None` means every level is accepted — Kanata sends a list only when a provider restricts levels; Kanata's `none`, `minimal`, `low`, `medium`, `high`, `xhigh` and `max` are all accepted, `none` being our `off`), an informational `context_tokens`, and `admission` — Kanata's private-listener block `{max_in_flight, max_queue, queue_ms, adapter_max_in_flight}` (needs a numeric `max_in_flight`; absent on the public listener and on plain Ollama). `AdmissionLimits::concurrency()` is min(route, adapter) and feeds the governor capacity check; nothing here enforces it. Kanata publishes operation names such as `chat`. Precedence per alias: the `kanata` object of its `GET /v1/models` entry, else operator-declared capabilities (an already-parsed map), else the minimal profile with no response format, sampling, reasoning or tools. The listing parser ignores unknown fields and skips unusable entries; a non-object `kanata` value is absent, and a wrong-typed field keeps its default (`function_tools` true, other flags false). `is_cloud` is an `external` zone or a `-cloud` alias suffix, because Ollama's cloud proxy reports `local`.

`LlmProvider::capabilities(model, deadline)` defaults to `None`, which leaves the request unshaped. The runner resolves capabilities exactly once per `complete` and sends every attempt through `complete_with(request, capabilities)`, so the wire body is built from the same resolution that was shaped and budgeted. With capabilities, the runner shapes before validation and accounting: a reasoning level outside a published `reasoning_efforts` list, or tools for a model without `function_tools`, fails with `UnsupportedCapability` before sending; without `structured_output` the output schema becomes one deterministic system instruction, merged into a leading system message or prepended, and the reply is still validated against the schema (unless the caller validates). That instruction counts toward the content, request and token bounds. The wire body includes `tools`, `response_format` (strict `json_schema`), `max_tokens`/`temperature`/`seed`/`top_p` and `reasoning_effort` only when the corresponding capability allows; `off` is sent as `"none"` unless a published `reasoning_efforts` list leaves `none` out, in which case it is omitted (model default); Kanata publishes no list when the provider passes every level through, so `None` allows all seven levels. Operator-declared capabilities follow the same rule: an endpoint that rejects `none` needs an explicit `reasoning_efforts` list, or its first `off` request downgrades `reasoning_control` for that alias. Values Kanata would refuse fail locally with `RequestInvalid` before anything is sent, but only for fields actually sent: a `response_format` name outside `[A-Za-z0-9_-]{1,64}`, a non-object schema, a schema over 64 KiB or 32 container levels; `max_tokens` outside 1..=1,048,576; a non-finite or out-of-range (0–2) `temperature`; `top_p` outside (0, 1]; a `seed` above `i64::MAX`; tool or tool-call names outside `[A-Za-z0-9_-]{1,64}`. Always refused: empty system or user content, an empty tool-call id, and an assistant turn with neither text nor tool calls. An empty tool result is sent (and counted) as the placeholder `(no output)`. Because only locally valid values are sent, a 400 naming a sent field is a genuine "unsupported" and downgrades the alias; a local failure never does. In schema-in-prompt mode, one Markdown fence around the whole reply is removed before validation.

## OpenAI-compatible HTTP adapter

`OpenAiCompatibleProvider` sends `POST {base}/v1/chat/completions` and `GET {base}/v1/models` to Kanata or a direct Ollama `/v1` endpoint. The adapter trims one trailing `/v1` and rejects userinfo, queries and empty path segments. It opens one HTTP/1.1 connection per exchange, never follows redirects, and applies one timeout to connect, TLS, request and body. TLS certificate or protocol errors are permanent, while a reset or EOF during the handshake is transient. Body caps are 1 MiB for completions, 256 KiB for listings and 64 KiB for error bodies; the runner's semantic limits still apply. Plain `http` is accepted only for loopback IPs, `localhost` (connected through loopback addresses only) and `host.docker.internal`; any other host is rejected with `HttpConfigError::InsecureHttp`. `https` always verifies certificates using the Rustls `ring` provider installed by `runtime::tls` (construction fails if it is missing). Roots come from the compiled `webpki-roots` set by default, independent of image CA packages, or from a replacement `TrustRoots::Custom` set, such as a private CA. The optional bearer key is caller-loaded secret bytes. It is sent as a sensitive header and never appears in `Debug` or error output.

A 401/403 is an authentication failure (Kanata's `key_expired` 401 surfaces as `ErrorCode::KeyExpired` so operators can tell a rotated-out key); a 504 is `UpstreamTimeout` (a backend phase timed out; Kanata's queue timeout is `503 gateway_busy`), as is the adapter's own exchange timeout and any reply lost after the request was handed to the connection (reset or EOF before the status line, a body cut short after any status line; reason `interrupted`) — the backend may have worked, so it is charged and never retried for chat; a plain 429 with `Retry-After` is `RateLimited {retry_after}` (transient, retried within the retry budget, but the backoff pause is at least `retry_after`; Kanata's own upstream 429 `rate_limit_exceeded` carries no `Retry-After`, so this only fires for direct endpoints); other 429 and 5xx replies are transient; a redirect or other 4xx is permanent. Kanata's codes are read from `error.code`, each only with the status Kanata sends it with: `429 gateway_queue_full`, `503 gateway_busy`, `429 gateway_key_busy` and `429 gateway_key_rate_limited` are `AdmissionRefused {retry_after}`; `503 server_draining` is also an admission refusal (breaker-neutral, requeued after the 1 s default); `503 upstream_unavailable` with `Retry-After` (Kanata's own breaker open) is `BackendUnavailable {retry_after}`, which opens our breaker at once for at least that long (capped at `max_open_cooldown`), while without `Retry-After` (adapter down or unbound) it is transient and counts toward our breaker threshold. `Retry-After` is honoured only as delta-seconds (capped at 3600 s); an HTTP-date is ignored. When a 400 `error.param` names an optional field that was sent (`response_format`, `temperature`, `seed`, `top_p`, `max_tokens` or `reasoning_effort`), the adapter records the downgrade for that alias for its lifetime (thread-safe) and returns `CapabilityRejected`. The runner then reshapes the original request without that capability (for example, adding the schema instruction), revalidates and reserves it again, and sends exactly one more request, whatever the transient attempt count; the rejected attempt keeps its reservation. A second rejection is permanent. Later calls start from the downgraded capabilities. A successful listing is authoritative for `catalog_ttl` (default 300 s), including for unlisted aliases. After that, one fetch is shared by concurrent callers. Each caller's budget is `catalog_timeout` (default 5 s) or half of the runner's remaining deadline, whichever is smaller. A caller that gets no listing falls back to declared or minimal capabilities. Only a fetch that fails, or that exceeds the full `catalog_timeout`, suppresses refetching for `catalog_failure_ttl` (default 30 s); running out of a shorter budget or waiting on another fetch never does. Replies are normalized as follows: a missing `model` echoes the request, a missing tool-call id becomes an unused `call_<index>`, and `stop` with tool calls becomes `tool_calls`. Governed requests carry `x-request-id: {session id}-{n}` (session ids are `kanade-{kind}-{instance}-{sequence}`, always within Kanata's 1–128 `[A-Za-z0-9_-]` rule; `Session::id()` exposes it) through `LlmProvider::complete_tagged`, which defaults to `complete_with`; ungoverned and listing requests send none, and Kanata generates its own. There is no idempotency header (Kanata has none), which is why a lost reply is charged and chat never resends it.

The adapter has been checked only against loopback stubs, including one synthetic self-signed TLS fixture. Environment and config-file wiring, key-file loading, and verification against the real Kanata gateway (auth and TLS) remain deferred to `integrate-kanata-last`. Direct Ollama normally uses declared capabilities because its listing has no `kanata` object.

## Identity codec

`infrastructure::llm::identity` is the seam every extraction and chat prompt goes through (pseudonymization stage 1). An `IdentityCodec` reports its `CodecMode` and opens an `IdentitySession` over the roster (`Member {user_id, display_name, nickname, aliases}`; `Debug` shows counts only): extraction opens one per request, chat one per conversation so identities stay consistent across rounds. Sessions encode author labels (`author_label(user_id, name)`), member refs for participant lists, extractor `participants` and tool arguments (`member_ref`, `participants`), mentions (`<@{member_ref}>`), free text and tool results; `participant_enum()` returns the refs issued so far for a strict schema enum (`None` = unconstrained); `decode_ref`, `decode_json` (tool arguments, structured output) and `decode_reply` map model output back, failing with `DecodeError::UnknownToken` (callers quarantine as malformed). Mapping state lives only in the session and is never persisted.

Only `Passthrough` ships: every encode and decode returns its input unchanged (labels are the Discord name, refs the decimal user id, `participant_enum` is `None`), so a request built through it is byte-identical to one built without a codec. Ports open sessions through `open_session(codec, route, roster)`, which runs `guard` on every call: a `RoleRoute` marked `external` is refused (`RouteRefused::ExternalWithoutPseudonymization`) while the codec is passthrough; `check_routes` applies the same guard to all routes at startup. The guard reads only the route's `external` marker, not `ModelCapabilities::is_cloud`. The on mode (random per-session tokens, leak scanner, env toggle) is stage 2. Test support adds `TaggingCodec` (sequential `ID<n>` tags, reports `Pseudonymizing`) and `find_leaks`/`find_request_leaks`, which list roster names, nicknames, aliases, roster ids and snowflake-length digit runs in captured requests.

## Model traffic governor

`infrastructure::llm::governor::Governor` is the single admission point for model traffic (chat, extraction, rescans, follow-ups, rewrites, pre-screen). Completions are obtained only through governed sessions: `CompletionRunner` has no public constructor or call outside feature `test-support` (whose `ungoverned` runner exists for provider contract tests).

Configuration: backend capacity groups `{name, backend, permits 1..=64, requests_per_min 1..=6000, burst 1..=1000 (default = permits), aliases}`; an alias belongs to exactly one group. Roles (`extraction`, `chat`, `rewrite`) map to `{alias, external}` and resolve to their alias's group. Validation refuses (first error, naming the group or role) out-of-range numbers, duplicate groups or aliases, empty names and policy values out of range. A role whose alias is in no group only warns; its calls are refused (`Ungrouped`), never run ungoverned. Once the gateway listing is known, `GovernorConfig::capacity_warnings(published)` (or `Governor::new_checked`) adds `PermitsAboveGateway {group, alias, permits, gateway}` for each alias whose published `admission.concurrency()` is below its group's permits; aliases with nothing published are not checked there (operator-declared limits are validated by the config API), and per-key limits are never published by Kanata, so they stay operator-declared. Policy defaults: breaker threshold 5, cooldown 30 s doubling per consecutive trip up to 300 s, drain step 5 s, retry budget 150‰ with a floor of 1 per 60 s window (permille ≤ 200).

- Permits: one permit covers a whole interaction. `acquire(role, ticket, wait)` queues by class — admin > in-flight chat rounds > new chat > extraction > follow-ups — FIFO within a class; it times out after `wait`, and dropping the future leaves the queue (or returns a permit granted in the same instant). While the breaker is open it is refused at once. Rewrite and pre-screen kinds may only `try_acquire`, which never waits, never jumps a queued waiter, and refuses pre-screen on an `external` route. It is refused while the breaker is open or a probe is in flight; half-open with no probe in flight it may take the single slot, and that holder's first request becomes the probe, so a group reached only through `try_acquire` (such as rewrite) still recovers. Dropping a `Permit` hands it to the next waiter.
- Requests: every provider request is admitted through its permit. `begin_request(max_wait)` checks the breaker, then takes a token-bucket token (`requests_per_min` refill, `burst` depth); tokens are reserved in order, so a caller waits its turn, and a wait longer than `max_wait` is refused without taking a token. The request (and any retry-budget spend) is recorded only once the wait ends and the breaker is re-checked; a request refused after its wait, or cancelled during it, refunds its token (capped at the burst) and records nothing, and a cancelled probe frees the probe slot. `try_begin_request` never waits. `begin_retry` additionally spends the group's retry budget: retries in the sliding window stay ≤ max(floor, permille × first attempts); retries do not count as requests. The caller reports each `Attempt` with `finish(outcome)`.
- Breaker per group: success or a permanent rejection resets the consecutive-failure count; transient failures and timeouts count toward the threshold; backend-unavailable opens at once (`Outcome::BackendUnavailableFor(d)` keeps it open at least `d`, capped at `max_open_cooldown`, so we never probe while the gateway's breaker is still open); admission refusals are neutral. Open refuses new work with `Unavailable {retry_at}` until the jittered probe time (cooldown × [1, 1.5), applied after the 300 s cap, so at most about 450 s), then half-open admits exactly one probe request (an abandoned or admission-refused probe frees the slot). A healthy probe closes the breaker and permits come back one per drain step, so queued work drains gradually alongside the rate ceiling; a failed probe reopens with a doubled cooldown. Outcomes of requests started before a trip are ignored while open.
- Time is tokio's clock (paused in tests); jitter comes from an injected `Random`; `snapshot(wall_now)` maps instants onto the caller's wall clock and returns per group the `BackendGroup` DTO fields of `docs/v5/limits-contract.md` (permits, dense 1-based queue with kind/who/waiting_s, rate level, retry remaining/capacity, breaker state/failures/since/retry_at — `retry_at` only while open) plus holders and cumulative counters (requests, retries, outcomes, sheds).
- Sessions: `ModelClient::new(governor, provider, limits, retry)` opens them; backoff jitter uses the governor's `Random`. Every provider request of a session (first attempts, transient retries, capability reshapes, requeues) passes `begin_request`/`begin_retry` on the session's permit, reports its outcome (success or a permanent rejection is healthy, transient/timeout count toward the breaker, backend-unavailable opens it, admission refusals are neutral; a request cut off by our own deadline is abandoned, i.e. neutral) and counts toward the session's request cap the moment it is admitted, so a `complete`/`clean_retry`/`answer_retry` future dropped mid-request (timeout, `select!`) still spends its request, a cancelled clean or answer retry still uses the reserved one, and an extraction call is marked started before it awaits, so a cancelled one cannot be repeated or retried. Requests must name the permit's alias.
  - `open_question(who, admin, QuestionLimits {tool_rounds 1..=12 (default 8), timeout})` queues in the admin or new-chat class within the timeout, which bounds the whole question. One permit is held across all tool rounds. `max_requests` = tool rounds + 1 (user decision Q2: default 9); `complete` may use all but one, which stays reserved for `clean_retry` — at most once, only while the breaker is closed and retry budget remains, spending that budget. Transient retries, reshapes and the requeue all draw from the same cap and deadline.
  - Slot loss: an `AdmissionRefused` reply is never retried directly. The session gives its permit back, waits `Retry-After` (1 s if absent, at least 250 ms) plus full jitter over the same span, requeues in the in-flight chat class (admins stay admin) and resends as a retry (spending retry budget) — exactly once per session, and only if the pause fits before the deadline, a request remains and the retry gate (breaker, retry budget) admits it; that gate is asked while the permit is still held, so a retry that could not happen fails at once (refunded) without releasing the slot. A clean retry skipped because the breaker is half-open is not counted as shed work. A timeout (504, transport, lost reply or deadline mid-request) is charged and ends the question; later calls fail with `Ended`.
  - `open_extraction(who, wait, timeout)` is a session at extraction priority: one `complete`, then at most one `answer_retry` (the caller rejected the reply it returned; v4's corrected-answer request) within the same permit. `max_requests` = the runner's attempts + 1 reshape + 1 reserved for the answer retry, which `complete` cannot use. The answer retry is a content retry: it counts toward the cap and deadline and is admitted like a first request (breaker and rate), not through the retry gate, so it spends no group retry budget; its own transient retries do. It is refused (`AnswerRetryUnavailable`) before a reply, after a failed or cancelled `complete`, or once used. Non-chat kinds may retry an upstream timeout within the retry budget.
  - `open_rewrite(who, timeout)` (nudge rewrites; not async) never waits: the `rewrite` role's permit comes from `try_acquire` and its rate token from `try_begin_request`, so a busy group, open breaker, in-flight probe or empty bucket is refused at once with nothing sent. `max_requests` = 1 and one `complete`: no transport retry, reshape, requeue or answer retry; `timeout` (1 ms..=300 s) bounds the request. Callers open the identity session through `open_session` like any other port (passthrough refuses `external` routes). In general, try-only kinds (rewrite, pre-screen) never wait for a rate token and are never admitted as retries.
  - `Refused::is_misconfiguration()` / `SessionError::is_misconfiguration()` split failures that need an operator or a code change (unknown or ungrouped role, route guard, `MustNotWait`, invalid request, unsupported capability, authentication, expired key, model mismatch) from "unavailable now" (busy, queue timeout, breaker, rate ceiling, retry budget, model failures).
  - Failures are `SessionError {failure, charge}`: `Refused` (governor), `RequestsExhausted`, `Ended`, `CleanRetryUnavailable`, `AnswerRetryUnavailable` or `Model(LlmError)`, each `Charged` or `Refunded` for the chat allowance. Charged means the backend produced a reply (invalid output, incomplete finish, content filter, model or usage mismatch included) or may still be working (any timeout); governor refusals, admission refusals, backend-unavailable, transient and permanent failures and local validation are refunded. New `ErrorCode`s: `AdmissionRefused`, `BackendUnavailable`, `UpstreamTimeout`.
